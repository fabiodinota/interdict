## Integration Gaps

### Gap 1: SAML ACS Cross-Origin Cookie Loss (IDENT-01) — HIGH

**File:** `control-plane/src/modules/auth/saml/handlers.ts` lines 116-129

The SAML ACS handler creates a session and sets an `interdict_session` httpOnly cookie on the control-plane domain (port 3000), then issues a 302 redirect to `DASHBOARD_URL` (port 8080). Browsers scope `Set-Cookie` to the responding origin — the cookie is invisible to the dashboard, so `dashboard/src/middleware.ts` sees no session and redirects back to `/login`.

**Note:** Phase 13 successfully wired all SAML env vars, cert generation, and IdP metadata mounts into both Docker Compose and Helm. The deployment activation path is complete. This is a code-level cross-phase wiring issue in the ACS → dashboard handoff.

**Fix:** After `createSession(user.id)`, redirect to a dashboard callback route (e.g., `DASHBOARD_URL/api/auth/saml-callback?token=<sessionToken>`) that runs server-side on the dashboard origin, sets the cookie there, then redirects to `/`.

### Gap 2: No Dashboard UI for Signing Key Management (IDENT-06) — LOW

No dashboard hook or page exists for `GET/POST /api/v1/admin/signing-keys/*`. The hot-reload mechanism is fully operational — admin can rotate keys via direct API calls and evidence-collector picks up new keys within 30 seconds via shared volume (both Docker Compose and Helm). However, the compliance dashboard provides no visibility into key status or rotation.

**Fix:** Add `use-signing-keys.ts` hook and `/settings/signing-keys` page.
