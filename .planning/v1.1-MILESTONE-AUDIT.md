## Integration Findings

### Critical — Deployment Wiring Gaps

#### 1. SAML SSO Has No Deployment Activation Path (IDENT-01)

Phase 10 delivers complete SAML 2.0 SP code (samlify 2.10.2, dual-mode auth middleware, JIT user provisioning, dashboard SSO button). The code is verified and functional. However:

- `env.example` has no SAML section (despite being "single source of truth")
- `docker-compose.yml` has no `SAML_*` environment variables for the control-plane service
- `docker-compose.yml` has no volume mount for `/config/` (IdP metadata)
- `helm/interdict/values.yaml` has no SAML section
- No SAML SP certificate generation script exists
- No operator documentation for enabling SSO

**Impact:** The milestone goal says "a CISO can log in via SSO." With default Docker Compose or Helm deployment, SSO is silently disabled. An operator has no guided path to activate it.

#### 2. Key Rotation Hot-Reload Not Plumbed in Deployment (IDENT-06)

Phase 10 delivers the admin rotation API, Postgres key registry, and RotatingSigningProvider with ArcSwap hot-reload. The code is verified. However:

- `SIGNING_KEY_WATCH_PATH` absent from evidence-collector in docker-compose.yml and Helm
- `SIGNING_KEY_OUTPUT_PATH` absent from control-plane in docker-compose.yml and Helm
- Helm `signing-keys` volume is `emptyDir: {}` (pod-local), not a shared PVC — control-plane and evidence-collector cannot share key material across pods

**Impact:** After rotation, evidence-collector continues signing with the old key until pod restart. The Postgres registry is correct (verification works), but zero-downtime rotation doesn't function in default deployments.
