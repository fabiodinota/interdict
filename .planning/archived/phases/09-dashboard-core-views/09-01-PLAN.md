## Task 2: Auth flow, layout, theme, BFF proxy, types, and Docker integration

<task>
<title>Implement auth flow, layout shell, theme toggle, BFF proxy, shared types, and Docker integration</title>
<context>
The control plane uses Bearer token auth (`Authorization: Bearer <api_key>`). The dashboard must:
1. Present a login page where the user pastes an API key
2. Store the API key in an httpOnly cookie via a Next.js API route (BFF pattern)
3. Proxy all API calls through Next.js API routes that inject the Bearer token from the cookie
4. Protect dashboard routes via Next.js middleware that checks for the session cookie

The layout follows the containerclaw pattern: persistent left sidebar (collapsible) + top bar + main content area with Suspense boundaries.

Theme uses next-themes with dark/light/system toggle, same as containerclaw.

The existing nginx placeholder Dockerfile at `docker/dashboard/Dockerfile` must be replaced with a proper Next.js multi-stage build Dockerfile. The `docker-compose.yml` dashboard service must be updated to match.

**Control plane API base URL inside Docker:** `http://control-plane:3000` (service name from docker-compose.yml).
**Dashboard internal port:** `3001` (to avoid conflict with control plane's 3000).
**Dashboard external port:** `8080` (host mapping, same as current placeholder).

**Auth endpoint to validate API key:** `GET /api/v1/auth/me` with `Authorization: Bearer <key>` header. Returns `{ success: true, data: { id, email, displayName, role, departmentIds } }`.

**Role hierarchy (lowest to highest):** read_only_auditor < department_manager < compliance_officer < policy_admin < super_admin
</context>

<steps>
1. Create `dashboard/src/types/api.ts` with TypeScript interfaces matching all control plane API response shapes. Include ALL types from the research document's "API Response Type Definitions" section:
   - `ApiResponse<T>`, `PaginatedResponse<T>`
   - `AuditRecord`, `Policy`, `PolicyVersion`, `Vendor`, `VendorModel`
   - `RegulatoryFramework`, `HourlyViolation`, `VendorUsage`
   - `AuthenticatedUser` with fields: `id`, `email`, `displayName`, `role`, `departmentIds`

2. Create `dashboard/src/lib/api.ts` -- centralized fetch wrapper for client-side API calls. All calls go through the BFF proxy (`/api/proxy/...`), NOT directly to the control plane:
   ```typescript
   const API_BASE = "";  // Same origin -- calls go to Next.js API routes

   export async function api<T>(path: string, options: RequestInit = {}): Promise<T> {
     const res = await fetch(`/api/proxy${path}`, {
       ...options,
       headers: {
         "Content-Type": "application/json",
         ...options.headers,
       },
     });
     if (!res.ok) {
       const error = await res.json().catch(() => ({ error: { message: res.statusText } }));
       throw new Error(error.error?.message || `API error ${res.status}`);
     }
     return res.json();
   }
   ```

3. Create `dashboard/src/lib/auth.ts` -- server-side auth utilities for reading the session cookie:
   ```typescript
   import { cookies } from "next/headers";

   const COOKIE_NAME = "interdict_session";

   export async function getSessionToken(): Promise<string | null> {
     const cookieStore = await cookies();
     return cookieStore.get(COOKIE_NAME)?.value ?? null;
   }

   export function getControlPlaneUrl(): string {
     return process.env.CONTROL_PLANE_URL || "http://localhost:3000";
   }
   ```

4. Create `dashboard/src/app/api/auth/login/route.ts` -- login API route:
   - Accepts POST with `{ apiKey: string }` body
   - Validates the key by calling `GET ${CONTROL_PLANE_URL}/api/v1/auth/me` with Bearer token
   - On success: sets `interdict_session` httpOnly cookie (secure in production, sameSite lax, 7-day maxAge, path /) and returns user data
   - On failure: returns 401 with error message
   - NEVER returns the raw API key in the response body

5. Create `dashboard/src/app/api/auth/logout/route.ts` -- logout API route:
   - POST handler that deletes the `interdict_session` cookie and returns success

6. Create `dashboard/src/app/api/auth/me/route.ts` -- current user API route:
   - GET handler that reads the session cookie, calls control plane `/api/v1/auth/me`, returns user data
   - Returns 401 if no session cookie

7. Create `dashboard/src/app/api/proxy/[...path]/route.ts` -- BFF proxy for all API calls:
   - Handles GET, POST, PUT, DELETE methods
   - Reads `interdict_session` cookie to get the API key
   - Forwards the request to `${CONTROL_PLANE_URL}/api/v1/${path.join("/")}` with Bearer token
   - Preserves query parameters and request body
   - Returns 401 if no session cookie
   - For SSE streaming (path ends with `audit/stream`): use a special handler that streams the response back using ReadableStream

8. Create `dashboard/src/middleware.ts` -- Next.js middleware for route protection:
   ```typescript
   import { NextResponse } from "next/server";
   import type { NextRequest } from "next/server";

   export function middleware(request: NextRequest) {
     const session = request.cookies.get("interdict_session");
     const isLoginPage = request.nextUrl.pathname === "/login";
     const isApiRoute = request.nextUrl.pathname.startsWith("/api/");

     // Allow API routes and static files through
     if (isApiRoute) return NextResponse.next();

     // Redirect to login if no session
     if (!session && !isLoginPage) {
       return NextResponse.redirect(new URL("/login", request.url));
     }

     // Redirect to dashboard if already logged in
     if (session && isLoginPage) {
       return NextResponse.redirect(new URL("/", request.url));
     }

     return NextResponse.next();
   }

   export const config = {
     matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
   };
   ```

    # docker/dashboard/Dockerfile -- Interdict Dashboard (Next.js)
    # Build context: repository root (.)
    # Usage: docker build -f docker/dashboard/Dockerfile .

    # Stage 1: Install dependencies
    FROM oven/bun:1 AS deps
    WORKDIR /app
    COPY dashboard/package.json dashboard/bun.lock ./
    RUN bun install --frozen-lockfile

    # Stage 2: Build
    FROM oven/bun:1 AS builder
    WORKDIR /app

    COPY dashboard/ .
    ENV NEXT_TELEMETRY_DISABLED=1

    FROM node:20-slim AS runner
