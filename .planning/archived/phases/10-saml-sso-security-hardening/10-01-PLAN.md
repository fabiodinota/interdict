  <action>
    **1. Install samlify:**
    `cd control-plane && bun add samlify@^2.10.0 @authenio/samlify-xsd-schema-validator`
    Pin samlify >= 2.10.0 (CVE-2025-47949 CVSS 9.9 in older versions).

    **2. Add sessions table to auth schema (control-plane/src/db/schema/auth.ts):**
    Add a `sessions` pgTable:
    - `id` uuid PK defaultRandom
    - `token` varchar(128) unique not null (crypto.randomBytes(64).toString('hex'))
    - `userId` uuid FK to users.id not null
    - `expiresAt` timestamp not null (default: 8 hours from creation)
    - `createdAt` timestamp defaultNow not null
    Index on `token` for fast lookup.

    **3. Create SAML SP configuration (control-plane/src/modules/auth/saml/config.ts):**
    - Import samlify, set schema validator via `samlify.setSchemaValidator(validator)`
    - Create ServiceProvider with:
      - entityID from env `SAML_SP_ENTITY_ID` (default: `https://interdict.example.com/saml/metadata`)
      - ACS binding HTTP-POST at `/api/v1/auth/saml/acs`
      - SLO binding HTTP-Redirect at `/api/v1/auth/saml/slo`
      - privateKey from file at `SAML_SP_KEY_PATH` (default: `/certs/saml-sp.key`)
      - signingCert from file at `SAML_SP_CERT_PATH` (default: `/certs/saml-sp.crt`)
      - nameIDFormat: emailAddress
      - wantAssertionsSigned: true
    - Create IdentityProvider from metadata XML file at `SAML_IDP_METADATA_PATH` (default: `/config/idp-metadata.xml`)
    - Export `sp`, `idp`, and a boolean `samlEnabled` (true only if cert files exist)
    - Configure `clockDrifts: [-300, 300]` for 5-minute tolerance
    - If cert files don't exist, log warning and set samlEnabled=false (graceful degradation)

    **4. Create SAML route handlers (control-plane/src/modules/auth/saml/handlers.ts):**
    - `GET /api/v1/auth/saml/sso` -- Initiate SSO: call `sp.createLoginRequest(idp, 'redirect')`, return 302 redirect to IdP
    - `POST /api/v1/auth/saml/acs` -- Assertion Consumer Service:
      1. Parse response: `sp.parseLoginResponse(idp, 'post', { body: request.body })`
      2. Extract nameID (email) and attributes (displayName, role)
      3. JIT provision: lookup user by email, if not found create with role from IdP attribute mapping (default: read_only_auditor). Set externalId to SAML nameID.
      4. Create session: insert into sessions table with crypto.randomBytes(64) token, 8h expiry
      5. Set httpOnly cookie `interdict-session` with token value (same cookie name/path as existing API key cookie flow)
      6. Redirect to dashboard URL (env `DASHBOARD_URL`, default: `http://localhost:8080`)
    - `GET /api/v1/auth/saml/slo` -- Single Logout: clear session cookie, redirect to IdP SLO if configured
    - `GET /api/v1/auth/saml/metadata` -- Return SP metadata XML (content-type application/xml)

    **5. Create metadata generator (control-plane/src/modules/auth/saml/metadata.ts):**
    - Export function that calls `sp.getMetadata()` and returns XML string

    **6. Extend auth service (control-plane/src/modules/auth/service.ts):**
    Add methods to AuthService interface and implementation:
    - `authenticateBySessionToken(token: string): Promise<AuthenticatedUser | null>` -- lookup in sessions table, check expiry, join with users table to get full AuthenticatedUser
    - `createSession(userId: string): Promise<string>` -- insert session row, return token
    - `findOrCreateSamlUser(email: string, displayName: string, externalId: string, roleHint?: string): Promise<AuthenticatedUser>` -- JIT provisioning logic

    **7. Extend auth middleware (control-plane/src/modules/auth/middleware.ts):**
    Modify the resolve handler to support dual-mode authentication:
    1. Extract Bearer token from Authorization header (unchanged)
    2. If token starts with `ik_live_` -> API key flow (existing logic)
    3. Otherwise -> session token flow: call `authService.authenticateBySessionToken(token)`
    4. If neither succeeds, return 401

    **8. Wire SAML routes into auth module (control-plane/src/modules/auth/index.ts):**
    - Import and mount SAML handlers as a sub-group under `/api/v1/auth/saml/`
    - Only mount if samlEnabled is true (conditional registration)
    - The ACS POST endpoint must NOT require auth (it creates the session)
    - The metadata endpoint must NOT require auth (IdPs fetch it)

    **Important:** SAML private keys MUST be file-mounted, never in env vars (CLAUDE.md invariant 6). All SAML config paths use file system references.
