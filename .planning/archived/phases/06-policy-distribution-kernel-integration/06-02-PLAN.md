<objective>
Wire the kernel's distribution gRPC client, refactor the PolicyPipeline to use ArcSwap-based hot-reload, integrate session context tracking into the proxy request flow, and spawn the distribution client from main.rs.

Purpose: This is the kernel-side integration that enables real-time policy updates from the control plane. After this plan, the kernel can connect to a gRPC distribution server, receive policy pushes, hot-reload them without restart, and track session context for multi-turn violation detection.

Output: Distribution client module (3 files), updated proxy/connect.rs with PolicySetManager, updated main.rs with distribution client spawn and session store.
</objective>

  <behavior>
    - apply_snapshot builds PolicySet from full list of PolicyEntry protos
    - apply_delta adds new policies and removes specified policy IDs from existing set
    - apply_delta detects version gap (received > current+1) and returns error requesting full snapshot
    - DistributionClient spawns reconnect loop that re-subscribes on stream drop
    - DistributionClient sends ACK/NACK after each update attempt
    - On NACK (apply failure), previous PolicySet is preserved (configurable rollback behavior)
    - Backoff follows gRPC spec: 1s initial, 1.6x multiplier, 120s max, 20% jitter
  </behavior>
  <action>
    1. Create `crates/kernel/src/policy/distribution/mod.rs`:
       - `pub mod client;`
       - `pub mod snapshot;`
       - Re-export generated proto types from build.rs output
       - Include the tonic::include_proto! for "interdict.policy.v1" (or similar path matching the proto package)

    2. Create `crates/kernel/src/policy/distribution/snapshot.rs`:
       - `apply_snapshot(entries: &[PolicyEntry], wasm_engine: &Arc<WasmEngine>, hierarchy_config: &HierarchyConfig) -> anyhow::Result<PolicySet>`:
         - Converts each PolicyEntry proto to ScopedPolicy + PolicyConfig
         - Maps FailMode proto enum to config::FailMode
         - Builds HierarchyResolver from all ScopedPolicy entries
         - Builds a new RegorusPool from all entries that have rego_source (use tokio::task::spawn_blocking per Pitfall 4 — Regorus operations are CPU-bound)
         - Computes content_hashes HashMap from policy_id -> wasm_hash
         - Constructs PolicySet with monotonic version from the update
       - `apply_delta(current: &PolicySet, update: &PolicyUpdate, wasm_engine: &Arc<WasmEngine>, hierarchy_config: &HierarchyConfig) -> anyhow::Result<PolicySet>`:
         - If version gap detected (update.version > current.version + 1), return Err indicating re-sync needed
         - Clone current policies, add new entries, remove entries in removed_policy_ids
         - Rebuild RegorusPool and HierarchyResolver from updated policy list (via spawn_blocking)
         - Return new PolicySet with updated version
       - Include unit tests for snapshot construction and delta application

    3. Create `crates/kernel/src/policy/distribution/client.rs`:
       - `DistributionClient` struct:
         - `addr: String`
         - `kernel_id: String`
         - `hierarchy_config: HierarchyConfig`
         - `policy_set_manager: Arc<PolicySetManager>`
         - `wasm_engine: Arc<WasmEngine>`
         - `disconnect_timeout: Duration`
         - `disconnect_mode: String` ("fail_closed" or "keep_last")
         - `cancel_token: tokio_util::sync::CancellationToken`
       - `DistributionClient::new(...)` constructor
       - `DistributionClient::run(self) -> JoinHandle<()>` — spawns the reconnect loop as a tokio task:
         ```
         loop {
             match connect_and_subscribe().await {
                 Ok(stream) => {
                     backoff = 1s; // reset on success
                     process_stream(stream).await;
                 }
                 Err(e) => log warning
             }
             // Check cancellation
             if cancel_token.is_cancelled() { break; }
             // Exponential backoff with jitter (gRPC spec)
             sleep(backoff +/- 20% jitter);
             backoff = min(backoff * 1.6, 120s);
         }
         ```
       - `connect_and_subscribe` — creates tonic Channel + PolicyDistributionClient, calls Subscribe with current version
       - `process_stream` — iterates stream, for each PolicyUpdate:
         - If FULL_SNAPSHOT: call apply_snapshot, on success swap via PolicySetManager, send ACK
         - If DELTA: call apply_delta, on success swap, send ACK; on version gap error, reconnect with version=0
         - On any apply error: send NACK, keep previous PolicySet (or fail-closed depending on disconnect_mode)
       - `DistributionClient::stop(&self)` — cancels the token for graceful shutdown
       - Send ACK/NACK via a separate unary RPC call (Acknowledge)

    4. Update `crates/kernel/src/policy/mod.rs`:
       - Ensure `pub mod distribution;` is declared (should be from Plan 01 but verify)
