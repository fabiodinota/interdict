<objective>
Implement Ed25519 signing key rotation for the evidence collector with admin API and hot-reload support.

The existing interdict-verify already supports multi-key verification via HashMap lookup, so the main work is: (1) key registry in PostgreSQL, (2) admin rotation API, (3) hot-swappable signing provider in the evidence collector.
Output: Signing key admin API, key registry table, RotatingSigningProvider, hot-reload mechanism.

    ```typescript
    export const signingKeys = pgTable("signing_keys", {
      id: uuid("id").primaryKey().defaultRandom(),
      keyId: varchar("key_id", { length: 64 }).notNull().unique(), // SHA-256(pubkey)[:16] hex
      publicKeyHex: varchar("public_key_hex", { length: 128 }).notNull(), // Full Ed25519 public key
      isActive: boolean("is_active").notNull().default(false), // Only ONE active at a time
      activatedAt: timestamp("activated_at"),
      retiredAt: timestamp("retired_at"),
      createdAt: timestamp("created_at").defaultNow().notNull(),
    });
    ```

    **2. Create signing keys service (control-plane/src/modules/signing-keys/service.ts):**
    Factory pattern matching existing services (createPolicyService, createAuthService):
    - `listKeys()` -- Returns all keys ordered by createdAt desc (active key first)
    - `getActiveKey()` -- Returns the one active key or null
    - `getAllPublicKeys()` -- Returns Record<key_id, public_key_hex> for verification (maps to interdict-verify's HashMap format)
    - `rotateKey()` -- The core rotation logic:
      1. Generate new Ed25519 keypair using `crypto.generateKeyPairSync('ed25519')` (or `ed25519-dalek` equivalent via a helper)
      2. Compute key_id as SHA-256(public_key_bytes)[:16] hex (matches LocalSigningProvider pattern)
      3. In a transaction:
         a. Set all existing keys' `isActive = false`, `retiredAt = now()`
         b. Insert new key with `isActive = true`, `activatedAt = now()`
      4. Return the new key's keyId and publicKeyHex (NEVER return private key material)
      5. The private key bytes must be returned ONCE to the caller so it can be distributed to the evidence collector (via file or config reload endpoint)
    - `registerExistingKey(keyId: string, publicKeyHex: string)` -- Register a key that was generated externally (e.g., by the evidence collector at startup in dev mode)

    **Note on private key distribution:** For v1.1, the rotation flow is:
    1. Admin calls POST /api/v1/admin/signing-keys/rotate
    2. Control plane generates keypair, stores public key in DB
    3. Control plane writes private key to a shared volume path (e.g., /keys/active-signing-key.pem)
    4. Evidence collector detects file change and hot-reloads
    This avoids sending private keys over the network.

    **3. Create signing keys API module (control-plane/src/modules/signing-keys/index.ts):**
    Elysia module with prefix `/api/v1/admin/signing-keys`:
    - `GET /` -- List all keys (keyId, isActive, activatedAt, retiredAt, createdAt). Requires super_admin role.
    - `POST /rotate` -- Trigger rotation. Generates new key, retires old one, writes private key to SIGNING_KEY_OUTPUT_PATH env var. Returns new key info (keyId, publicKeyHex). Requires super_admin role.
    - `GET /active` -- Get the current active key's public info. Requires policy_admin+ role.
    - `GET /public-keys` -- Get all public keys as Record<keyId, publicKeyHex> (for verification tools). Requires read_only_auditor+ role.
    - All endpoints use the auth macro with appropriate role guards.

    **4. Wire module into main app (control-plane/src/index.ts):**
    - Import and `.use()` the signingKeysModule
    - Follow same pattern as existing module registration

    **1. Create RotatingSigningProvider (crates/evidence-collector/src/signing/rotation.rs):**
    ```rust
    use std::sync::Arc;
    use tokio::sync::RwLock;
    use async_trait::async_trait;
    use super::{SigningProvider, SigningError, LocalSigningProvider};

    pub struct RotatingSigningProvider {
        active: Arc<RwLock<Arc<dyn SigningProvider>>>,
    }
    ```

    Implement:
    - `new(initial: Arc<dyn SigningProvider>) -> Self` -- wraps the initial signing provider
    - `rotate(&self, new_provider: Arc<dyn SigningProvider>)` -- atomically swaps active key via RwLock write lock. Log old key_id being retired and new key_id becoming active.
    - `reload_from_file(&self, key_path: &str) -> Result<(), SigningError>` -- reads key file, creates new LocalSigningProvider, calls rotate(). This is the hot-reload entry point.

    Implement `SigningProvider` for `RotatingSigningProvider`:
    - `sign()` -- acquire read lock, delegate to active provider
    - `public_key()` -- acquire read lock (but this is sync -- need to handle. Use `try_read()` or cache the value. Alternative: store a cached copy of public_key bytes and key_id that gets updated on rotate)
    - `key_id()` -- same as public_key
    - `is_dev_key()` -- delegate to active

    **Design note:** The `SigningProvider` trait has sync methods (`public_key()`, `key_id()`). Using `RwLock::blocking_read()` in sync context is acceptable here since it's only contended during the brief rotation swap. Alternatively, store atomic cached values:
    - `cached_public_key: Arc<RwLock<Vec<u8>>>`
    - `cached_key_id: Arc<RwLock<String>>`
    Updated on every rotation. The sign() method uses the async RwLock path.

    Actually, simpler approach: use `ArcSwap` from `arc-swap` crate (add to Cargo.toml) which provides lock-free atomic Arc swaps:
    ```rust
    use arc_swap::ArcSwap;
    pub struct RotatingSigningProvider {
        active: ArcSwap<dyn SigningProvider>,
    }
    ```
    This avoids the sync/async lock mismatch entirely. `active.load()` is wait-free for reads, `active.store()` for rotation.

    If arc-swap is too heavy, use `std::sync::RwLock` (not tokio) since all trait methods are sync and sign() can use blocking_read() (the async sign on the inner provider still works because it's called from async context).
