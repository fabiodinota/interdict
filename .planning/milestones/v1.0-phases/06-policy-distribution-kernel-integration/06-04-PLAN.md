ROADMAP Phase 6 Success Criteria:
1. When a compliance officer updates a policy via the control plane API, the compiled Wasm module is pushed to all connected kernel instances via gRPC server-streaming within seconds, without any kernel polling
2. Kernels load the new policy module at runtime without restarting the binary, and subsequent AI requests are evaluated against the updated policy
3. Policies can be configured per department, per user, and per AI vendor, with an inheritance model where organization defaults cascade to department overrides to team overrides
4. The kernel tracks session context across multi-turn conversations per user/session, detecting policy violations that emerge across multiple exchanges (e.g., slow-leak data exfiltration)

    - test_disconnect_keeps_last: After disconnect, last-known policies remain active
  </behavior>
  <action>
    Create `crates/kernel/tests/distribution_test.rs`:

    Note: These are unit-level integration tests that validate the kernel-side distribution logic without requiring a running gRPC server. They test the snapshot/delta processing, PolicySetManager swap mechanics, and hierarchy resolution at the component level.

    1. `test_sc1_full_snapshot_updates_policy_set`:
       - Create empty PolicySetManager (version=0)
       - Build a list of PolicyEntry protos with 2 policies (one org-level, one dept-level)
       - Call apply_snapshot to build PolicySet
       - Swap into PolicySetManager
       - Assert version advanced from 0 to snapshot version
       - Assert content_hashes has entries for both policies
       - Assert PolicySetManager::load() returns the new version
       - This proves SC1: "compiled Wasm module is pushed to all connected kernel instances" — the kernel-side reception and application works

    2. `test_sc2_hot_reload_new_policy_evaluated`:
       - Create PolicySetManager with initial PolicySet containing one Rego policy that ALLOWs all
       - Create a RequestContext for "api.openai.com"
       - Verify evaluation against initial policy returns Allow
       - Build new PolicySet with a Rego policy that BLOCKs "api.openai.com"
       - Swap into PolicySetManager
       - Load new set and evaluate again
       - Assert result is now Block
       - This proves SC2: "subsequent AI requests are evaluated against the updated policy"

    3. `test_sc3_hierarchy_org_dept_team_cascade`:
       - Create ScopedPolicy entries:
         - Org-level: Allow all traffic (scope: org="acme", dept=None, team=None)
         - Dept-level: Block vendor "risky-ai.com" (scope: org="acme", dept="legal", team=None)
         - Team-level: Block vendor "another-ai.com" (scope: org="acme", dept="legal", team="litigation")
       - Create HierarchyResolver
       - Test case 1: User in org="acme", dept=None, team=None → only org policy (Allow)
       - Test case 2: User in org="acme", dept="legal", team=None → org + dept policies. For "risky-ai.com": Block (dept overrides). For "safe-ai.com": Allow (org only)
       - Test case 3: User in org="acme", dept="legal", team="litigation" → all three levels. For "another-ai.com": Block (team-level)
       - Merge verdicts with MergedVerdict::merge to prove most-restrictive-wins
       - This proves SC3: "organization defaults cascade to department overrides to team overrides"

    4. `test_sc3_hierarchy_per_vendor_scoping`:
       - Create policies scoped to specific vendor_ids
       - Verify that a policy scoped to "api.openai.com" does NOT apply to "api.anthropic.com"
       - Verify that a policy with empty vendor_ids applies to ALL vendors

    5. `test_delta_add_policy`:
       - Start with PolicySet containing 1 policy
       - Apply delta that adds 1 new policy
       - Assert resulting PolicySet has 2 policies

    6. `test_delta_remove_policy`:
       - Start with PolicySet containing 2 policies
       - Apply delta with removed_policy_ids containing one of them
       - Assert resulting PolicySet has 1 policy

    7. `test_delta_version_gap_detection`:
       - Start with PolicySet at version=5
       - Apply delta with version=8 (gap: expected 6)
       - Assert error indicating version gap / re-sync needed

    8. `test_disconnect_preserves_last_known`:
       - Create PolicySetManager with a loaded PolicySet at version=10
       - Simulate "disconnect" by NOT swapping
       - Assert PolicySetManager::load() still returns version=10 (last-known preserved)
       - This validates the "keep last-known policies" disconnect behavior
  </action>
