<objective>
Build the Layer 3 human review queue with SQLite persistence, connection-hold semantics, and timeout/fail-mode handling. This is the async escalation path for genuinely ambiguous requests where the NLP classifier returns 'uncertain'.

Purpose: Layer 3 is the safety net for cases that deterministic rules and ML can't resolve. The queue holds the user's connection for 30-60 seconds while waiting for a human reviewer, then applies the policy's fail-mode if no decision arrives. The SQLite backend persists queue state for dashboard integration in Phase 8/9.

Output: layer3/queue.rs (in-memory queue with connection hold via oneshot channels), layer3/store.rs (SQLite persistence layer).
</objective>

  <action>
    Implement the in-memory review queue that holds connections per Research Pattern 3:

    **1. `ReviewQueue` struct:**
    - `store: Arc<ReviewQueueStore>` — persistence backend
    - `pending: Arc<DashMap<String, tokio::sync::oneshot::Sender<HumanVerdict>>>` — maps request_id → oneshot sender for connection hold
    - `semaphore: Arc<tokio::sync::Semaphore>` — limits concurrent L3 holds (default 50 from config.l3_max_pending_reviews per Pitfall 6)
    - `default_timeout: Duration` — from config.l3_timeout_seconds (default 30s per locked decision)

    **2. `ReviewQueue::new(store: Arc<ReviewQueueStore>, max_pending: usize, default_timeout: Duration) -> Self`**

    **3. `ReviewQueue::escalate(&self, request_id: uuid::Uuid, trace: &VerdictTrace, content_hash: &str, fail_mode: FailMode) -> Result<VerdictAction>`:**
    This is the core method called when L2 returns 'uncertain':
    - Try acquire semaphore permit (non-blocking `try_acquire`). If fails → concurrent L3 limit hit → immediately return fail_mode.default_action(). Log warning "L3 queue at capacity, applying fail-mode" per Pitfall 6
    - Create `oneshot::channel()` for the response
    - Persist to SQLite store (enqueue with timeout_at = now + default_timeout)
    - Insert sender into pending DashMap keyed by request_id
    - Await the receiver with `tokio::time::timeout(self.default_timeout, rx)`:
      - `Ok(Ok(verdict))` → human decided → return verdict.action
      - `Ok(Err(_))` → channel dropped (reviewer disconnected) → return fail_mode.default_action()
      - `Err(_)` → timeout → log "L3 review timeout, applying fail-mode" → update store status to 'expired' → return fail_mode.default_action()
    - Clean up: remove from pending DashMap (in all paths — use defer/drop guard or explicit cleanup)
    - Drop semaphore permit when done (automatic with RAII)

    **4. `ReviewQueue::submit_verdict(&self, request_id: &str, verdict: HumanVerdict) -> Result<bool>`:**
    Called by the management API when a human reviewer decides:
    - Update SQLite store: submit_verdict with action, reviewer_id, reason
    - Look up request_id in pending DashMap
    - If found, send verdict through the oneshot sender (unblocks the held connection)
    - If not found (already timed out), return false
    - Return true if verdict was delivered

    **5. `ReviewQueue::get_pending_count(&self) -> usize`** — returns pending DashMap len (for monitoring)

    **6. `ReviewQueue::get_pending_items(&self) -> Result<Vec<QueueItem>>`** — delegates to store.get_pending() (for management API)

    **7. `HumanVerdict` struct:** `{ action: VerdictAction, reviewer_id: String, reason: String }`

    Write unit tests:
    - `test_escalate_holds_connection_until_verdict` — escalate in background task, submit verdict from main task, verify escalate returns the submitted verdict
    - `test_escalate_timeout_returns_fail_mode_closed` — escalate with short timeout (100ms), don't submit verdict, verify Block returned (fail-closed)
    - `test_escalate_timeout_returns_fail_mode_open` — same but fail-open, verify Allow returned
    - `test_escalate_concurrent_limit` — fill semaphore, next escalate returns fail-mode immediately without waiting
    - `test_submit_verdict_after_timeout_returns_false` — escalate with short timeout, wait for timeout, then submit verdict → returns false
    - `test_escalate_persists_to_store` — after escalate, verify store.get_by_request_id returns the item
    - **All tests must use in-memory SQLite and short timeouts (100ms) for fast execution**

    **CRITICAL:** All channels must be bounded (KERN-13). The oneshot channel is inherently bounded (single value). The semaphore provides the concurrency bound. No unbounded channels anywhere.
