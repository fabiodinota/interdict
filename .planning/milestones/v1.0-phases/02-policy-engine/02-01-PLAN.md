    **2. Create `crates/kernel/src/policy/layer1/regorus.rs`:**
    Implement the Regorus engine pool per Research Pattern 1:
    - `RegorusPool` struct using `crossbeam_queue::ArrayQueue<regorus::Engine>` and `Arc<tokio::sync::Semaphore>`
    - `RegorusPool::new(template: &regorus::Engine, size: usize) -> Self` — clones template engine `size` times, pushes into ArrayQueue
    - `RegorusPool::evaluate(&self, input_json: &str, rule: &str) -> Result<PolicyVerdict>` — acquires semaphore permit, pops engine, uses `tokio::task::spawn_blocking` (Regorus is sync — CRITICAL per Pitfall 2), calls `engine.set_input()` + `engine.eval_rule()`, parses result into PolicyVerdict, pushes engine back
    - Parse Rego verdict result: expect JSON with `{"action": "allow"|"block"|"redact", "reason": "...", "redactions": [...]}`. Map to PolicyVerdict. If the Rego rule returns unexpected format, treat as the policy's fail_mode action
    - `RegorusPool::load_policy(policy_id: &str, rego_source: &str) -> Result<regorus::Engine>` — creates a fresh Engine, calls `engine.add_policy(policy_id, rego_source)`, returns the engine. This is the template builder
    - Handle errors: if eval_rule returns error or engine panics in spawn_blocking, return the policy's configured fail_mode action (FailClosed → Block, FailOpen → Allow) per CONTEXT.md locked decision about consistent error handling
    - **CRITICAL:** Never call `engine.eval_rule()` directly on the async tokio runtime. Always use `spawn_blocking`. This is Pitfall 2 from research
    - **CRITICAL:** After eval, MUST return engine to the pool (even on error). Use RAII pattern or ensure push happens in all code paths
    - Write unit tests:
      - `test_regorus_evaluate_allow_verdict` — load a simple Rego policy that allows, verify PolicyVerdict.action == Allow
      - `test_regorus_evaluate_block_verdict` — load policy that blocks a specific vendor, verify Block
      - `test_regorus_evaluate_redact_verdict` — load policy returning redact with patterns, verify Redact with redactions
      - `test_regorus_pool_concurrent_evaluations` — spawn 10 concurrent evaluations against pool of size 4, all complete
      - `test_regorus_pool_returns_engine_on_error` — invalid input, engine returned to pool (pool still usable after)

    **3. Create `crates/kernel/src/policy/wasm_engine.rs`:**

    - `WasmEngine::new(config: &PolicyEngineConfig) -> Result<Self>`:

        - `total_core_instances(config.wasm_max_instances)` (default 64)
        - `total_memories(config.wasm_max_instances)`
        - `total_tables(config.wasm_max_instances)`
        - `max_memory_size(config.wasm_max_memory_bytes)` (default 1MB — CRITICAL per Pitfall 1 to avoid 4GB virtual memory per slot)
        - `max_core_instance_size(1 << 16)` (64KB VMContext)
        - `max_memories_per_module(1)`
        - `max_tables_per_module(1)`
        - `max_unused_warm_slots(16)` (keep warm for reuse)
      - Set `cranelift_opt_level(Speed)`
    - `WasmEngine::engine(&self) -> &wasmtime::Engine` — getter for downstream use
    - `WasmEngine::load_module(&self, wasm_bytes: &[u8]) -> Result<wasmtime::Module>` — compiles Wasm bytes using the engine. For pre-compiled modules: `unsafe { Module::deserialize(engine, bytes) }`
    - Write unit tests:

      - `test_wasm_engine_respects_memory_limits` — verify config values are applied (check via engine.config() or by creating instances)
