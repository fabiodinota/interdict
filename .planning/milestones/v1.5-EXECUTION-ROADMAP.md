# v1.5 Production Readiness — Phased Execution Roadmap

**Status:** planning
**Created:** 2026-03-14
**Source:** Comprehensive Foundation Assessment (2026-03-14) + ASSESSMENT_COMMENTS.md fix plan
**Scope:** Close every gap, concern, advisory, weakness, and risk identified in the multi-agent deep audit. No new product features — this is a pure hardening and operational maturity milestone.

## Why This Milestone Exists

The 2026-03-14 assessment confirmed that Interdict's architecture and Rust code quality are A+, but identified meaningful gaps in:
- Hot-path test coverage (relay code with zero tests)
- Release automation (no CI/CD pipeline for image publishing)
- Operational tooling (no E2E tests, no secret scanning, no monitoring)
- Dashboard accessibility and CSP hardening
- Documentation for operators

These gaps must be closed before scaling beyond the current two-partner pilot and before any GA release. Total distinct action items: ~45, organized into 8 phases.

## Hard Ordering Rules

1. **Phase 34** (hot-path tests) must land first — it covers the most critical untested code paths.
2. **Phase 35** (Layer 3 + signing tests) can proceed in parallel with Phase 34 if different engineers work on them.
3. **Phase 36** (dependency cleanup + constructor safety) has no dependencies, can proceed anytime.
4. **Phase 37** (expanded test coverage) depends on Phase 34–35 patterns being established.
5. **Phase 38** (CI/CD release pipeline) has no code dependencies but should land before Phase 39.
6. **Phase 39** (security hardening) depends on Phase 38 for secret scanning CI integration.
7. **Phase 40** (DevOps maturity) depends on Phase 38 (release pipeline) for image registry work.
8. **Phase 41** (documentation + accessibility) is last — it documents the final state after all other changes land.

## Phase 34: Hot-Path Relay Testing

**Goal:** Bring the most critical untested code paths — the proxy relay and streaming relay — from 0% to ≥80% coverage with meaningful unit and integration tests.

**Assessment references:** Test Coverage B- → target A-, "Critical gap: proxy/streaming_relay.rs and proxy/relay.rs"

### Tasks

#### T01: Unit tests for `proxy/relay.rs`

**File:** `crates/kernel/src/proxy/relay.rs` (~730 lines)

Write tests covering:
- Bidirectional relay completes successfully for normal HTTP traffic
- Relay handles upstream connection reset gracefully (no panic, returns error)
- Relay handles client disconnect mid-stream (cleanup, no resource leak)
- Cross-chunk pattern detection with 256-byte overlap window
- Zero-copy behavior verification (no unnecessary allocations)
- Timeout behavior when upstream stops sending
- Large payload relay (>1MB) completes without OOM

**Verification:**
```bash
cargo test -p kernel relay -- --nocapture
```

#### T02: Unit tests for `proxy/streaming_relay.rs`

**File:** `crates/kernel/src/proxy/streaming_relay.rs` (~480 lines)

Write tests covering:
- Bidirectional streaming copy completes successfully
- Evidence collection callback fires for each chunk
- Streaming relay handles partial writes correctly
- Buffer management under backpressure (bounded, no unbounded growth)
- Connection termination propagates in both directions
- Error in evidence callback does not kill the relay (graceful degradation)
- Concurrent readers/writers do not race

**Verification:**
```bash
cargo test -p kernel streaming_relay -- --nocapture
```

#### T03: Unit tests for `proxy/tls.rs`

**File:** `crates/kernel/src/proxy/tls.rs`

Write tests covering:
- TLS connection establishment with valid certificates
- TLS handshake failure returns proper error (not panic)
- Certificate validation using webpki_roots
- mTLS mutual authentication when configured
- Connection with expired certificate is rejected

**Verification:**
```bash
cargo test -p kernel tls -- --nocapture
```

#### T04: Integration test — full proxy relay flow

Create `crates/kernel/tests/relay_integration_test.rs`:
- Spin up a mock upstream HTTPS server
- Connect through the kernel proxy
- Verify request/response integrity end-to-end
- Verify evidence events are emitted for the relay
- Verify cross-chunk PII detection works in relay context

**Verification:**
```bash
cargo test -p kernel --test relay_integration_test
```

### Exit Criteria

- All relay/streaming/TLS modules have ≥80% line coverage
- Zero `unwrap()` or `expect()` in new test helper code that could mask failures
- All tests pass in CI across vpc-native, sidecar, air-gapped modes
- No regressions in existing test suite
