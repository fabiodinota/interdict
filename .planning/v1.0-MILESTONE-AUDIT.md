**Milestone:** v1.0

## Executive Summary

All 6 phases (Kernel Proxy Foundation, Policy Engine, PII Detection, Evidence Collector, Control Plane API, Policy Distribution) have been individually built, tested, and verified. Every phase VERIFICATION.md passed. All 49 milestone requirements are marked complete in REQUIREMENTS.md and backed by passing tests at the phase level.

However, **cross-phase integration checking** reveals two P0 wiring gaps in the kernel binary entry point (`main.rs` and `connect.rs`) that render 11 requirements non-functional at runtime despite passing isolated tests:

1. **ContentInspector not instantiated** — PII detection, injection blocking, and stream severing are compiled and tested but never activated in the running binary.
2. **PolicySetManager hot-reload not driving enforcement** — Policy distribution delivers and swaps correctly, but the enforcement path ignores the swapped policies.

Both gaps are small fixes (5-10 lines each) but are blocking for milestone completion.

## Integration Gaps (P0 — Blocking)

### INT-01: ContentInspector Not Instantiated in main.rs

**From:** Phase 3 — `ContentInspector`, `PatternRegistry`, `InjectionDetector`, `InspectingRelay`
**To:** Phase 1 — `ProxyService` in `crates/kernel/src/main.rs`
**Break:** `ProxyService` constructed without calling `.with_content_inspector()`. The `content_inspector` field is `None` at runtime.
**Effect:** All PII detection (PII-01 through PII-06), sliding window buffer (KERN-05), stream severing (KERN-06), and prompt injection detection (PLCY-11) are dead code in the running binary. `handle_connect()` branches to zero-copy `relay::bidirectional()` instead of `inspecting_relay_outbound()`.
**Fix:** ~5 lines in main.rs after ProxyService construction:
```rust
let pattern_registry = policy::patterns::PatternRegistry::default_registry();
let inspector = Arc::new(policy::content_inspection::ContentInspector::new(
    pattern_registry, redaction_engine.clone(),
));
let proxy_service = proxy_service.with_content_inspector(inspector);
```
**Affected:** PII-01, PII-02, PII-03, PII-04, PII-05, PII-06, KERN-05, KERN-06, PLCY-11

### INT-02: PolicySetManager Hot-Reload Not Driving Enforcement

**From:** Phase 6 — `DistributionClient` → `PolicySetManager::swap()`
**To:** Phase 2 — `PolicyPipeline.evaluate()` in `handle_connect()`
**Break:** `ProxyService::call()` at `connect.rs:518-526` calls `psm.load()` for debug logging only. The loaded `PolicySet` is never passed to `handle_connect()` or used for evaluation. The static `PolicyPipeline` (created at startup with an empty policy list) evaluates all requests.
**Effect:** Kernel receives and stores updated policies from the control plane but continues enforcing the static empty pipeline. Hot-reload swap is invisible to enforcement.
**Fix:** Wire `PolicySetManager.load()` policies into the evaluation path in `handle_connect()`, either by passing the current `PolicySet` to the pipeline or by constructing a request-scoped pipeline from the live set.
**Affected:** PLCY-06, CTRL-03
