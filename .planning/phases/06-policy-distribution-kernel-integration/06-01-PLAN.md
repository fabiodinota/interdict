  <behavior>
    - PolicySet::new creates a valid set with version, content_hashes, hierarchy config
    - PolicySetManager::load() returns lock-free Arc snapshot of current PolicySet
    - PolicySetManager::swap() atomically replaces PolicySet; subsequent load() returns new version
    - HierarchyResolver::resolve() gathers org + dept + team policies for a given context
    - HierarchyResolver with org Block + dept Allow returns Block (most-restrictive-wins)
    - HierarchyResolver filters by vendor_id when scope includes vendor restrictions
    - HierarchyResolver with empty dept/team returns only org-level policies
    - Proto compiles via build.rs with tonic client stubs generated
  </behavior>
  <action>
    1. Create `proto/interdict/policy/v1/policy_distribution.proto`:
       - `service PolicyDistribution { rpc Subscribe(SubscribeRequest) returns (stream PolicyUpdate); rpc Acknowledge(AckRequest) returns (AckResponse); }`
       - `SubscribeRequest`: kernel_id, current_version (u64, 0 for full snapshot), org_id, dept_id, team_id
       - `PolicyUpdate`: version (u64), type (FULL_SNAPSHOT=0, DELTA=1), repeated PolicyEntry policies, repeated string removed_policy_ids
       - `PolicyEntry`: policy_id, name, version (u64), wasm_bytes, wasm_hash (SHA-256), rego_source, entrypoint, PolicyScope scope, FailMode fail_mode (FAIL_CLOSED=0, FAIL_OPEN=1)
       - `PolicyScope`: org_id, dept_id, team_id, repeated vendor_ids
       - `AckRequest`: kernel_id, version, accepted (bool), error_message
       - `AckResponse`: acknowledged (bool)

    2. Update `crates/kernel/build.rs`:
       - Add the new proto to compile_protos array: `"../../proto/interdict/policy/v1/policy_distribution.proto"`
       - Keep existing evidence proto compilation
       - Client only (build_server=false) since kernel is the client

    3. Add `arc-swap = "1.7"` to `crates/kernel/Cargo.toml` under [dependencies]

    4. Create `crates/kernel/src/policy/hot_reload.rs`:
       - `PolicySet` struct:
         - `regorus_pool: Arc<RegorusPool>` (the full rebuilt pool from new Rego sources)
         - `wasm_engine: Arc<WasmEngine>` (shared, not rebuilt per update)
         - `hierarchy: HierarchyResolver` (rebuilt from policy scope data)
         - `policies: Vec<PolicyConfig>` (full list with hierarchy already resolved)
         - `version: u64` (monotonic version counter from control plane)
         - `content_hashes: HashMap<String, String>` (policy_id -> SHA-256 of wasm)
       - `PolicySetManager` struct:
         - `inner: Arc<ArcSwap<PolicySet>>`
       - `PolicySetManager::new(initial: PolicySet) -> Self`
       - `PolicySetManager::load() -> arc_swap::Guard<Arc<PolicySet>>` — lock-free read for hot path
       - `PolicySetManager::swap(new: PolicySet)` — atomic store for distribution client
       - `PolicySetManager::current_version() -> u64` — read version without full load
       - Include unit tests verifying atomic swap semantics

    5. Create `crates/kernel/src/policy/hierarchy.rs`:
       - `HierarchyConfig`: org_id, dept_id (Option), team_id (Option)
       - `ScopedPolicy`: wraps PolicyConfig + PolicyScope (org_id, dept_id, team_id, vendor_ids)
       - `HierarchyResolver` struct:
         - `org_policies: Vec<ScopedPolicy>`
         - `dept_policies: HashMap<String, Vec<ScopedPolicy>>` (dept_id -> policies)
         - `team_policies: HashMap<String, Vec<ScopedPolicy>>` (team_id -> policies)
       - `HierarchyResolver::new(policies: Vec<ScopedPolicy>) -> Self` — distributes policies into org/dept/team buckets
       - `HierarchyResolver::resolve(ctx: &HierarchyConfig, vendor: &str) -> Vec<PolicyConfig>` — gathers applicable policies from all levels, filters by vendor
       - Per CONTEXT.md: "No per-user policy overrides — users inherit from their team"
       - Per CONTEXT.md: "Lower levels can only tighten, never loosen org-level protections" — this is handled by MergedVerdict::merge (most-restrictive-wins), hierarchy just gathers ALL applicable policies
       - Include unit tests: org-only, org+dept, org+dept+team, vendor filtering, most-restrictive-wins via MergedVerdict

    6. Update `crates/kernel/src/policy/mod.rs`:
       - Add `pub mod hierarchy;`, `pub mod hot_reload;`, `pub mod session;`
       - Add `pub mod distribution;` (empty module that will be filled in Plan 02)

    7. Update `crates/kernel/src/config.rs`:
       - Add `DistributionConfig` struct to `PolicyEngineConfig` or as separate section:
         - `distribution_addr: Option<String>` (control plane gRPC addr, e.g. "http://[::1]:50052")
         - `kernel_id: Option<String>` (override kernel ID, defaults to UUID)
         - `org_id: String` (required for hierarchy resolution)
         - `dept_id: Option<String>`
         - `team_id: Option<String>`
         - `disconnect_timeout_secs: u64` (default 30, time before fail-closed on disconnect)
         - `disconnect_mode: String` (default "fail_closed", alt "keep_last")
         - `session_max_entries: usize` (default 10000)
         - `session_ttl_secs: u64` (default 1800 = 30 min)
         - `session_cleanup_interval_secs: u64` (default 60)
       - Add `#[serde(default)]` on the distribution config field
       - Add default value functions for all fields

<task type="auto" tdd="true">
  <name>Task 2: Create bounded session context store</name>
  <files>
    crates/kernel/src/policy/session.rs
  </files>
  <behavior>
    - SessionStore::get_or_create returns new entry for unknown session ID
    - SessionStore::get_or_create returns existing entry for known session ID
    - SessionStore::record_exchange appends exchange and updates detection state
    - SessionStore::cleanup_expired removes entries older than TTL
    - SessionStore enforces max_sessions limit with LRU eviction
    - DetectionState::update increments total_redactions and tracks categories_seen
    - DetectionState::should_escalate returns true when slow-leak thresholds exceeded (N distinct PII categories across M exchanges)
    - Session boundary detection: uses X-Session-Id header when present, falls back to user_id+vendor+30min window
  </behavior>
  <action>
    Create `crates/kernel/src/policy/session.rs`:

    1. `ExchangeRecord` struct:
       - `request_hash: String` (SHA-256 of prompt)
       - `response_hash: String` (SHA-256 of response, empty string if not yet available)
       - `timestamp: chrono::DateTime<chrono::Utc>`
       - `verdict: VerdictAction`
       - `categories_detected: Vec<String>` (PII categories found in this exchange)

    2. `DetectionState` struct:
       - `total_redactions: u32`
       - `categories_seen: HashSet<String>`
       - `cumulative_risk_score: f32`
       - `exchange_count: u32`
       - Implement `Default`
       - `update(&mut self, record: &ExchangeRecord)` — increment counters, add categories
       - `should_escalate(&self) -> bool` — returns true if slow-leak detected:
         - If categories_seen.len() >= 3 AND exchange_count >= 3: potential slow-leak exfiltration
         - If total_redactions >= 5 within a session: high volume redaction pattern
         - If cumulative_risk_score >= 3.0: threshold exceeded
         These are configurable via SessionConfig.

    3. `SessionEntry` struct:
       - `session_id: String`
       - `user_id: String`
       - `vendor: String`
       - `exchanges: Vec<ExchangeRecord>`
       - `detection_state: DetectionState`
       - `created_at: std::time::Instant`
       - `last_activity: std::time::Instant`
       - Derive Clone

    4. `SessionConfig` struct:
       - `max_sessions: usize` (default 10000)
       - `session_ttl: Duration` (default 30 min)
       - `cleanup_interval: Duration` (default 60s)
       - `slow_leak_category_threshold: usize` (default 3)
       - `slow_leak_exchange_threshold: usize` (default 3)
       - `redaction_volume_threshold: u32` (default 5)
       - `risk_score_threshold: f32` (default 3.0)

    5. `SessionStore` struct:
       - `sessions: DashMap<String, SessionEntry>`
       - `config: SessionConfig`
       - `SessionStore::new(config: SessionConfig) -> Self`
       - `get_or_create(session_id: &str, user_id: &str, vendor: &str) -> SessionEntry` — returns clone
       - `record_exchange(session_id: &str, record: ExchangeRecord) -> Option<bool>` — returns Some(should_escalate) if session exists, None if not found
       - `cleanup_expired(&self)` — retain only entries where last_activity < ttl. Called periodically.
       - `session_count(&self) -> usize`
       - `evict_if_full(&self)` — if sessions.len() >= max_sessions, remove oldest by last_activity (LRU)

    6. `resolve_session_id(headers: &http::HeaderMap, user_id: &str, vendor: &str) -> String`:
       - Check for `X-Session-Id` or `X-Conversation-Id` header
       - If found, use that value
       - If not found, generate deterministic session ID from `sha256(user_id + vendor)` truncated to 16 hex chars + time-window bucket (current timestamp / 1800 seconds, i.e. 30-min windows)
       - Per Claude's Discretion: dual approach handles cooperative and uncooperative clients

    7. Include comprehensive unit tests:
       - get_or_create new session
       - get_or_create existing session (returns same data)
       - record_exchange updates detection state
       - cleanup_expired removes stale entries
       - evict_if_full with max_sessions=2 removes oldest
       - should_escalate slow-leak detection scenarios
       - resolve_session_id with header present
       - resolve_session_id without header (inferred)
  </action>
  <verify>
    <automated>cargo test -p kernel session -- --nocapture</automated>
  </verify>

  </done>
