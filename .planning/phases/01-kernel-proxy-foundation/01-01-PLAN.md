    Implement the TLS certificate infrastructure that generates domain-specific certificates signed by the deployment CA.

    **crates/kernel/src/proxy/tls.rs:**

    **`load_ca(config: &TlsConfig) -> Result<(rcgen::CertifiedKey, rcgen::KeyPair), ProxyError>`:**
    - Read CA cert PEM from `config.ca_cert_path` and CA key PEM from `config.ca_key_path`
    - Parse into rcgen types. The CA cert is used to sign per-domain end-entity certificates.
    - If files don't exist or are malformed, return `ProxyError::Config` (fail-closed per CONTEXT.md)

    **`CertCache` struct:**
    - `cache: DashMap<String, Arc<rustls::ServerConfig>>` -- thread-safe cert cache keyed by domain
    - `ca_cert: rcgen::Certificate` (or equivalent rcgen type for the issuer cert)
    - `ca_key: rcgen::KeyPair` (CA's private key for signing)

    **`CertCache::new(ca_cert, ca_key)` constructor**

    **`CertCache::get_or_create(&self, domain: &str) -> Result<Arc<rustls::ServerConfig>, ProxyError>`:**
    - Fast path: if `self.cache.get(domain)` returns Some, return the cached `Arc<ServerConfig>` (sub-microsecond)
    - Slow path (cert cache miss):
      1. Create `rcgen::CertificateParams` with `domain` as SAN (Subject Alternative Name)
      2. Generate a new `rcgen::KeyPair` for the end-entity cert
      3. Sign with CA: `cert_params.signed_by(&key_pair, &self.ca_cert, &self.ca_key)?`
      4. Build `rustls::ServerConfig` with:
         - `.with_no_client_auth()` (client certs not needed for proxy-to-client TLS)
         - `.with_single_cert(cert_chain, private_key)` where cert_chain includes the new cert DER
      5. Wrap in `Arc`, insert into DashMap, return clone
    - Use `DashMap::entry()` API to prevent thundering herd: only one task generates a cert per domain (per research Pitfall 4)
    - Wrap the CPU-bound cert generation in `tokio::task::spawn_blocking()` (per research Pitfall 5: blocking in async context)

    **`CertCache::pre_warm(&self, domains: &[String]) -> Result<(), ProxyError>`:**
    - Call `get_or_create` for each domain in the list
    - Log each pre-warmed domain at debug level
    - Called at startup from main.rs with the allowlist vendor domains

    **Important rcgen API notes (from research State of the Art):**
    - rcgen 0.13+ API: `CertificateParams::signed_by()` takes `&KeyPair` and `&Certificate` separately, NOT a combined `CertifiedKey`
    - The CA cert needs to be parsed from PEM into rcgen's type system
    - Use `rcgen::CertificateParams::new(vec![domain.to_string()])` for the domain SAN
    - Set appropriate certificate properties: not_before = now, not_after = now + 1 day (short-lived certs are fine since they're cached and regenerated)

    **Unit test in the same file (#[cfg(test)]):**
    - Test: generate a CA keypair programmatically, create CertCache, call get_or_create twice for same domain, verify second call returns cached value (check DashMap len stays at 1)
    - Test: generate cert for "api.openai.com", verify it has the correct SAN
    - Test: pre_warm populates cache for all provided domains
