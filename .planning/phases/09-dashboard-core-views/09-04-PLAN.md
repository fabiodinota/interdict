## Task 1: Audit Trail data table with search and filters

<task>
<title>Build audit trail search page with TanStack Table, server-side pagination, and filter panel</title>
<context>
The audit trail is the most data-intensive view. It shows all AI interactions and policy decisions with:
- Server-side search and filtering (the API does the filtering, not the browser)
- Cursor-based pagination (the API returns a `nextCursor` for the next page)
- Filter panel with: vendor, department, policy action (allow/block/redact), date range (from/to)
- Columns: timestamp, actor, vendor, model, policy action, token count, latency, department

**API endpoint:** GET /api/v1/audit/search with query params:
- vendor, department, actor, policy_action (allow|block|redact), from_date, to_date, kernel_id
- cursor (for pagination), page_size (default 50)
- Returns: `{ success: true, data: AuditRecord[], pagination: { nextCursor, hasMore } }`

**Key pattern:** Use TanStack Table with `manualPagination: true`. The table does NOT manage its own data -- it receives data from the TanStack Query hook and delegates pagination to the API.

Filter state should be synced with URL search params so the user can bookmark/share filtered views.
</context>

<steps>
1. Create `dashboard/src/hooks/use-audit.ts` -- TanStack Query hooks for audit data:
   - `useAuditSearch(filters: AuditFilters, cursor?: string, pageSize?: number)`:
     - Query key includes all filter values and cursor
     - Uses `keepPreviousData` to avoid loading flashes during page changes
     - Returns typed `PaginatedResponse<AuditRecord>`
   - `AuditFilters` interface: `{ vendor?: string, department?: string, policy_action?: string, from_date?: string, to_date?: string }`

2. Create `dashboard/src/components/audit/AuditFilters.tsx`:
   - Filter panel above the table
   - Layout: horizontal row of filter controls on desktop, stacked on mobile
   - Filter controls:
     - Vendor: shadcn Select populated with vendors from API (use a quick `useVendorOptions()` hook)
     - Department: shadcn Input (free text, or Select if departments are available from user context)
     - Policy Action: shadcn Select with options: All, Allow, Block, Redact
     - Date Range: two date inputs (From / To) using shadcn Calendar + Popover for date picking
       - Presets: Today, Last 7 days, Last 30 days, Custom
   - "Apply Filters" button and "Clear" button
   - Filter state synced with URL search params using `useSearchParams()` and `useRouter()`

3. Create `dashboard/src/components/audit/AuditTable.tsx`:
   - Uses TanStack Table with `manualPagination: true`
   - Column definitions:
     - Timestamp: formatted with date-fns (`format(parseISO(ts), "MMM d, yyyy HH:mm:ss")`)
     - Actor: `actor_display_name || actor_identity` (truncated with tooltip for full value)
     - Department: `department_display_name || department`
     - Vendor: `vendor_display_name || vendor` with model in subtle text below
     - Policy Action: Badge component (allow=green, block=red, redact=orange)
     - Token Count: formatted number
     - Latency: `enforcement_latency_us` displayed as ms (divide by 1000, round to 1 decimal)
   - Uses shadcn Table components for rendering (not raw HTML table)
   - Pagination controls at bottom: "Previous" / "Next" buttons
     - "Next" button disabled when `hasMore === false`
     - Page navigation uses cursor-based approach: store cursors for each page visited
   - Loading skeleton state (skeleton rows matching table column count)
   - Empty state: "No audit records found matching your filters"
   - Row click could expand to show raw evidence hash details (optional nice-to-have)

4. Update `dashboard/src/app/(dashboard)/audit/page.tsx`:
   - Replace placeholder with AuditFilters + AuditTable
   - Page title: "Audit Trail" with subtitle "Search and filter AI interactions and policy decisions"
   - Filter state managed at page level, passed to both AuditFilters and AuditTable
   - Initial load with no filters (shows most recent records)
</steps>

## Task 2: Vendor Management, Regulatory Selector, and Report Generation

<task>
<title>Build Vendor Management UI, Regulatory Framework Selector, report generation endpoint, and report download UI</title>
<context>
This task covers three distinct views plus a new control plane endpoint:

**Vendor Management (DASH-04):**
- List all vendors with approve/block status toggle
- Per-vendor: see all models with individual approve/block toggles
- Add new vendor dialog
- Status changes reflect in kernel enforcement "within seconds" via gRPC distribution

**Regulatory Framework Selector (DASH-05):**
- List all frameworks as cards with activation toggle
- Click framework to see its policies with individual enable/disable toggles
- Shows framework metadata: jurisdiction, version, policy count, active count

**Report Generation (DASH-06):**
- New control plane endpoint: POST /api/v1/reports/generate
- Takes: format (pdf|csv), from_date, to_date
- Returns: generated file as binary download
- Report content: executive summary, policy violations by type/department/vendor, audit trail highlights (top 10 incidents), active policies list, vendor approval status, regulatory framework compliance status, date range on every page
- Dashboard UI: date range picker with presets (Last 7 days, Last 30 days, Last quarter, Year to date, Custom), format selector (PDF/CSV), generate button with progress indicator, download on completion

**API endpoints:**
- Vendors: GET/POST/PUT/DELETE /api/v1/vendors, POST/PUT/DELETE /api/v1/vendors/:id/models
- Regulatory: GET /frameworks, GET /frameworks/:slug, POST /frameworks/:slug/activate, POST /frameworks/:slug/deactivate, PUT /frameworks/:slug/policies/:policyId/toggle
- Reports: NEW -- POST /api/v1/reports/generate (must be created in the control plane)
</context>
