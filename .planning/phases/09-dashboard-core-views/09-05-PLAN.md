## Goal

Fix the single blocking gap identified by the phase verifier: the BFF proxy at `dashboard/src/app/api/proxy/[...path]/route.ts` unconditionally calls `res.json()` (line 74) on all non-SSE responses. When the control plane returns `application/pdf` or `text/csv` content from `POST /api/v1/reports/generate`, the JSON parse throws and the proxy returns 502, making PDF and CSV report downloads impossible.

After this plan, the proxy detects the upstream `Content-Type` and pipes binary/text responses through with the original headers (including `Content-Disposition`), so the `use-reports.ts` blob download flow works end-to-end.

All other behavior (JSON responses, SSE streaming, auth, error handling) must remain identical.

Replace ONLY the try block with a version that:

1. Reads the upstream `Content-Type` response header BEFORE attempting any body parsing.
2. Defines a helper `isJsonResponse` that returns `true` when the content type starts with `application/json` or is absent (treat missing content type as JSON, which is the control plane default).
3. For JSON responses: keep the existing behavior (`res.json()` -> `NextResponse.json(data, { status })`).
4. For non-JSON responses (PDF, CSV, or any other binary/text content type): pipe the raw body back to the client:
   - Use `new Response(res.body, { ... })` to stream the raw body without buffering.
   - Forward the upstream `status` code exactly.
   - Forward these upstream headers to the client response: `Content-Type`, `Content-Disposition`, `Content-Length` (if present). Do NOT forward any other upstream headers.
   - If `res.body` is null (should not happen in practice), fall back to returning a 502 error.

The replacement block should look like this (implement exactly):

```typescript
  try {
    const res = await fetch(url, fetchOptions);
    const upstreamContentType = res.headers.get("content-type") ?? "";
    const isJsonResponse =
      upstreamContentType === "" ||
      upstreamContentType.startsWith("application/json");

    if (isJsonResponse) {
      const data = await res.json();
      return NextResponse.json(data, { status: res.status });
    }

    // Non-JSON response (binary PDF, text/csv, etc.) -- pipe raw body through
    if (!res.body) {
      return NextResponse.json(
        { success: false, error: { message: "Empty upstream response body" } },
        { status: 502 }
      );
    }

    const responseHeaders = new Headers();
    responseHeaders.set("Content-Type", upstreamContentType);
    const contentDisposition = res.headers.get("content-disposition");
    if (contentDisposition) {
      responseHeaders.set("Content-Disposition", contentDisposition);
    }
    const contentLength = res.headers.get("content-length");
    if (contentLength) {
      responseHeaders.set("Content-Length", contentLength);
    }

    return new Response(res.body, {
      status: res.status,
      headers: responseHeaders,
    });
  } catch (err) {
    // JSON parse failures are now scoped only to actual JSON responses
    return NextResponse.json(
      { success: false, error: { message: "Proxy request failed" } },
      { status: 502 }
    );
  }
```

**Important constraints:**
- Do NOT change the SSE streaming block (lines 28-55) -- it works correctly and must remain untouched.
- Do NOT change the auth check, URL construction, or header forwarding in the non-streaming path -- only replace the try block at the bottom.
- The `isJsonResponse` check must treat an empty/missing content type as JSON (not non-JSON) to preserve backward compatibility with any control plane endpoints that omit the Content-Type header.
