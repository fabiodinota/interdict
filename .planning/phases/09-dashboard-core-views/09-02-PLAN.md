## Task 1: KPI cards, chart components, and time range selector

<task>
<title>Build KPI cards, violation line chart, vendor usage bar chart, and time range selector</title>
<context>
The dashboard home screen shows:
- Top row: 4 KPI cards (Total Requests Today, Violations Today, Active Policies, Active Vendors)
- Below: A time range selector (24h / 7d / 30d) shared by both charts
- Left chart: Violation trend line chart (from `/api/v1/audit/stats/violations?from=...&to=...`)
- Right chart: Vendor usage bar chart (from `/api/v1/audit/stats/vendor-usage?from=...&to=...`)
- Manual refresh button + last-updated timestamp on chart panels

All chart data is fetched via TanStack Query with 30-second `refetchInterval` for polling.

**Recharts library** is locked for all charts.

The KPI data comes from a combination of existing API endpoints:
- Total requests today: derive from violations stats (sum all actions) OR create a simple count from audit/search with today's date
- Violations today: sum of "block" + "redact" actions from violations stats
- Active policies: GET /api/v1/policies (count items where is_active=true)
- Active vendors: GET /api/v1/vendors?status=approved (count items)

All API calls go through the BFF proxy: `/api/proxy/audit/stats/violations`, etc.
</context>

## Task 2: SSE activity feed with reconnection

<task>
<title>Build SSE activity feed hook and component for real-time audit events</title>
<context>
The activity feed shows real-time audit events streamed via Server-Sent Events (SSE). The control plane has an SSE endpoint at `/api/v1/audit/stream` that requires Bearer token auth.

**Problem:** The browser's native `EventSource` API does NOT support custom headers (Authorization: Bearer).

**Solution:** The BFF proxy at `/api/proxy/audit/stream` reads the API key from the httpOnly cookie and connects to the control plane SSE endpoint with the Bearer token. It then streams events back to the client. The client connects to `/api/proxy/audit/stream` using native EventSource (no auth header needed since the cookie is sent automatically).

The SSE endpoint yields events with `event: "audit-event"` and `data: JSON.stringify(auditRecord)`.

**Requirements:**
- Cap events at 50 (discard oldest when limit reached)
- Auto-reconnect on disconnect (5-second delay)
- Show connected/disconnected status indicator
- Cleanup EventSource on component unmount
</context>

<steps>
1. Update the BFF proxy route (`dashboard/src/app/api/proxy/[...path]/route.ts`) to handle SSE streaming:
   - When the path matches `audit/stream`, use a special SSE proxy handler
   - Read the API key from the cookie
   - Connect to `${CONTROL_PLANE_URL}/api/v1/audit/stream` using `fetch()` with Bearer token
   - Return a streaming response using `ReadableStream` that pipes the upstream SSE data through
   - Set response headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`
   - Handle upstream connection errors gracefully

2. Create `dashboard/src/hooks/useSSE.ts` -- reusable SSE hook:
   ```typescript
   // Parameters: url (string), options ({ maxEvents?: number })
   // Returns: { events: SSEEvent[], connected: boolean, clear: () => void }
   //
   // Behavior:
   // - Creates EventSource connection to the given URL
   // - Listens for "audit-event" events
   // - Prepends new events to the array (newest first)
   // - Caps array at maxEvents (default 50), discarding oldest
   // - Auto-reconnects on error after 5 seconds
   // - Sets connected=true on "connected" event
   // - Cleans up EventSource on unmount
   // - clear() empties the events array
   ```

3. Create `dashboard/src/components/dashboard/ActivityFeed.tsx`:
   - Uses `useSSE("/api/proxy/audit/stream")` to get real-time events
   - Displays events in a scrollable list inside a shadcn Card
   - Card title: "Live Activity" with a green/red dot indicating connection status
   - Each event row shows:
     - Timestamp (formatted relative time with date-fns `formatDistanceToNow`)
     - Actor display name or identity
     - Vendor + model
     - Policy action badge: allow (green), block (red), redact (orange) using shadcn Badge
   - Empty state: "Waiting for events..." with a subtle pulse animation
   - Maximum height with scroll: h-96 with ScrollArea
   - "Clear" button to reset the feed

4. Integrate ActivityFeed into the home page (`dashboard/src/app/(dashboard)/page.tsx`):
   - Place below the chart grid
   - Full width
   - The activity feed is always visible regardless of time range selection (SSE is real-time, not historical)
</steps>
