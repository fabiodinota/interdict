  <action>
    **1. Create cert generation script (docker/certs/generate-internal-ca.sh):**
    Use openssl CLI (simpler for a deployment bootstrap script than compiling a Rust binary):
    - Generate internal CA key + self-signed cert (10-year validity, CN=interdict-internal-ca)
    - Generate server cert+key for evidence-collector (SAN: DNS:evidence-collector, DNS:localhost)
    - Generate server cert+key for control-plane (SAN: DNS:control-plane, DNS:localhost)
    - Generate client cert+key for kernel (SAN: DNS:kernel, DNS:localhost)
    - All service certs signed by the internal CA (1-year validity)
    - Output all files to `/certs/` directory:
      - `/certs/internal-ca.pem` (CA cert -- shared by all services for peer verification)
      - `/certs/evidence-collector.pem`, `/certs/evidence-collector-key.pem`
      - `/certs/control-plane.pem`, `/certs/control-plane-key.pem`
      - `/certs/kernel-client.pem`, `/certs/kernel-client-key.pem`
    - Script should be idempotent: skip generation if `/certs/internal-ca.pem` already exists (check with `[ -f /certs/internal-ca.pem ]`)
    - Make script executable: `chmod +x docker/certs/generate-internal-ca.sh`

    **2. Add cert-init service to docker-compose.yml:**
    - Add a `cert-init` service using `alpine/openssl` or `alpine:latest` (with `apk add openssl`)
    - Mount `./docker/certs/generate-internal-ca.sh` as read-only and `/certs` as a named volume
    - Command: `sh /scripts/generate-internal-ca.sh`
    - No restart policy -- runs once and exits
    - All gRPC services (kernel, control-plane, evidence-collector) get:
      - `depends_on: cert-init: condition: service_completed_successfully`
      - Volume mount: `certs:/certs:ro`
    - Add named volume `certs` to volumes section

    **3. Update env.example:**
    Add new mTLS-related env vars with comments:
    - `MTLS_ENABLED=true` -- toggle for mTLS (allows fallback to insecure for local dev without Docker)
    - `MTLS_CA_CERT_PATH=/certs/internal-ca.pem`
    - `MTLS_CERT_PATH` (service-specific, e.g., `/certs/evidence-collector.pem`)
    - `MTLS_KEY_PATH` (service-specific)

    **4. Update kernel entrypoint (docker/kernel/entrypoint.sh):**
    Change default addresses from `http://` to `https://`:
    - `KERNEL_DISTRIBUTION_ADDR` default: `https://control-plane:50052`
    - `KERNEL_EVIDENCE_COLLECTOR_ADDR` default: `https://evidence-collector:50051`
    Add env var defaults for cert paths:
    - `KERNEL_MTLS_CA_CERT=/certs/internal-ca.pem`
    - `KERNEL_MTLS_CLIENT_CERT=/certs/kernel-client.pem`
    - `KERNEL_MTLS_CLIENT_KEY=/certs/kernel-client-key.pem`

    **Important:** The cert generation uses openssl CLI in a lightweight Alpine init container, NOT rcgen. While rcgen is in the project, a shell script is simpler for a one-shot deployment bootstrap task that doesn't need Rust compilation. rcgen is appropriate for runtime cert generation (like the existing TLS interception CA) but not for static deployment certs.

      - Use `Server::builder().tls_config(tls)?` instead of plain `Server::builder()`
    - If MTLS_ENABLED=false: keep existing insecure server (backward compatible for local dev)
    - Add `tonic::transport::{Identity, Certificate, ServerTlsConfig}` imports
    - Update config.rs to add mtls fields (ca_cert_path, cert_path, key_path, mtls_enabled)

    **2. Update control plane gRPC distribution server (control-plane/src/modules/distribution/server.ts):**
    - Read env vars: `MTLS_ENABLED`, `MTLS_CA_CERT_PATH`, `MTLS_CERT_PATH`, `MTLS_KEY_PATH`
    - If MTLS_ENABLED=true:
      - Read CA cert, server cert, server key using `readFileSync`
      - Replace `grpc.ServerCredentials.createInsecure()` with:
        ```
        grpc.ServerCredentials.createSsl(
          caCert,                    // rootCerts -- CA for validating client certs
          [{ cert_chain: serverCert, private_key: serverKey }],
          true                       // checkClientCertificate = true
        )
        ```
    - If MTLS_ENABLED=false: keep existing `createInsecure()` (backward compatible)
    - Import `readFileSync` from `node:fs`

    **3. Update kernel evidence gRPC client (crates/kernel/src/evidence/client.rs):**
    - Add optional TLS configuration to `EvidenceGrpcClient`:
      - New field: `tls_config: Option<ClientTlsConfig>`
      - In constructor, if env `KERNEL_MTLS_CA_CERT` is set, build ClientTlsConfig:
        ```rust
        let tls = ClientTlsConfig::new()
            .ca_certificate(Certificate::from_pem(ca_cert))
            .identity(Identity::from_pem(client_cert, client_key))
            .domain_name("evidence-collector");
        ```
      - In `connect_inner`, if tls_config is Some, call `endpoint.tls_config(tls)?` before `.connect()`
    - Add `tonic::transport::{ClientTlsConfig, Certificate, Identity}` imports
    - The TLS config must be cloneable or reconstructed per connection attempt (tonic ClientTlsConfig is not Clone -- read cert bytes once, store as fields, rebuild config per connect)

    **4. Update kernel distribution gRPC client (crates/kernel/src/policy/distribution/client.rs):**
    - Same pattern as evidence client: add optional `tls_config` support
    - If env `KERNEL_MTLS_CA_CERT` is set, attach ClientTlsConfig to Endpoint
    - domain_name: "control-plane"
    - Apply to all three Endpoint::from_shared calls in the file (lines ~153, ~277, and any reconnect paths)

    **5. Update kernel config (crates/kernel/src/config.rs):**
    - Add mTLS config fields: `mtls_ca_cert_path`, `mtls_client_cert_path`, `mtls_client_key_path`
    - Parse from env vars: `KERNEL_MTLS_CA_CERT`, `KERNEL_MTLS_CLIENT_CERT`, `KERNEL_MTLS_CLIENT_KEY`
    - Pass through to EvidenceGrpcClient and distribution client constructors

    **Critical:** Both tonic servers and clients must reference the SAME internal CA. The CA cert is the trust anchor. Server certs are validated by clients using the CA. Client certs are validated by servers using the CA. All signed by the same CA from the cert-init container.

    **Backward compatibility:** When MTLS_ENABLED is not set or "false", all services fall back to insecure mode. This keeps local `cargo test` and development without Docker working. The Docker Compose environment sets MTLS_ENABLED=true.
