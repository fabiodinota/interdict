    - Test: Getting a framework by slug returns its policies with requirement references
    - Test: Activating a framework creates an activation record and marks is_active=true
    - Test: Activating a framework does NOT affect existing custom policies (additive behavior)
    - Test: Deactivating a framework sets is_active=false and records deactivated_at timestamp
    - Test: Toggling off an individual framework policy sets its is_required=false
    - Test: Re-activating a previously deactivated framework works correctly
    - Test: Listing active frameworks filters to only currently active ones
  </behavior>
  <action>
    **src/modules/regulatory/model.ts:**
    - TypeBox schemas:
      - `FrameworkResponse`: id, slug, name, description, jurisdiction, version, is_seeded, is_active (derived from latest activation), policies (array of framework policy objects with requirement_ref, requirement_description, policy_id, policy_name, is_required, compilation_status)
      - `FrameworkListResponse`: array of frameworks with activation status summary (policy count, active policy count)
      - `ActivateFrameworkBody`: optional notes (string)
      - `TogglePolicyBody`: is_required (boolean)

    **src/modules/regulatory/service.ts (RegulatoryService):**
    - `list()`: Query all frameworks with their latest activation status. For each, include policy count and active (is_required=true) policy count. Return sorted by name.
    - `getBySlug(slug)`: Fetch framework with all its policies joined to the policies table (for name, compilation_status). Include requirement_ref and requirement_description per policy. Throw NotFoundError if slug not found.
    - `activate(frameworkId, activatedBy?)`: Insert into framework_activations with is_active=true. If already active, no-op and return current state. Per CONTEXT.md: enabling is additive -- does NOT disable other frameworks or custom policies.
    - `deactivate(frameworkId)`: Update latest activation record to is_active=false, set deactivated_at. If not active, no-op.
    - `togglePolicy(frameworkPolicyId, isRequired)`: Update framework_policies.is_required. This allows disabling individual policies within an active framework without deactivating the whole framework.
    - `getActiveFrameworks()`: Query frameworks with active activations, include their policies.
    - `getActivePolicies()`: Return all policy IDs that should be active based on: (1) directly active custom policies AND (2) policies from active frameworks where is_required=true. This is the additive merge per CONTEXT.md decision.

    **src/modules/regulatory/index.ts (regulatoryModule):**
    - Elysia plugin with prefix `/api/v1/regulatory`:
      - `GET /frameworks` -- list all frameworks with activation status
      - `GET /frameworks/:slug` -- get framework details with policies
      - `POST /frameworks/:slug/activate` -- activate framework
      - `POST /frameworks/:slug/deactivate` -- deactivate framework
      - `PUT /frameworks/:slug/policies/:policyId/toggle` -- toggle individual policy
      - `GET /active-policies` -- get all currently active policy IDs (additive merge)

    Wire `regulatoryModule` into the main Elysia app in `src/index.ts`.
  </action>

    **Seed framework metadata (JSON files):**

    Each `framework.json` contains:
    ```json
    {
      "slug": "eu-ai-act",
      "name": "EU AI Act",
      "description": "European Union Artificial Intelligence Act (Regulation 2024/1689)",
      "jurisdiction": "EU",
      "version": "2024",
      "policies": [
        {
          "file": "policies/transparency-notice.rego",
          "requirement_ref": "Article 13 - Transparency",
          "requirement_description": "AI systems must provide clear information about their AI nature and capabilities to users",
          "is_required": true,
          "sort_order": 1
        }
      ]
    }
    ```

    **EU AI Act Rego policies (5 policies):**

    Each Rego policy must:
    - Use package `interdict.policy.verdict` (matching kernel's expected entrypoint)
    - Accept `input` with the structure: `{ vendor, method, path, content_type, content, direction }`
    - Return a verdict object: `{ "action": "block|allow|redact", "reason": "...", "redactions": [...] }`
    - Be a REAL working policy that enforces the relevant regulation, not a stub

    1. **transparency-notice.rego**: Block requests that don't include transparency metadata in content. Check for prompts that generate content without disclosure ("write as if human", "pretend you're not AI"). Return block verdict with reason referencing Article 13.

    2. **human-oversight.rego**: Flag automated decision-making prompts without human review indicators. Detect prompts requesting final decisions on hiring, lending, legal matters. Return block with reason referencing Article 14.

    3. **risk-assessment.rego**: Block high-risk AI usage without risk assessment context. Detect prompts related to biometric identification, critical infrastructure, law enforcement. Return block referencing Article 9.

    4. **data-governance.rego**: Enforce data quality requirements. Detect prompts containing training data or datasets without governance markers. Return redact/block referencing Article 10.

    5. **incident-reporting.rego**: Detect potential serious incidents. Flag prompts indicating system failures, safety concerns, or bias detection. Return block referencing Article 62.

    **GDPR Rego policies (5 policies):**

    1. **purpose-limitation.rego**: Block prompts that indicate data processing beyond stated purpose. Detect requests to use personal data for undeclared purposes ("also use this data for marketing"). Return block referencing Article 5(1)(b).

    2. **data-minimization.rego**: Flag prompts requesting more personal data than necessary. Detect excessive data collection patterns. Return redact with reason referencing Article 5(1)(c).

    3. **consent-verification.rego**: Block processing personal data without consent indicators. Detect prompts processing identifiable individuals' data without consent context. Return block referencing Articles 6-7.

    4. **right-to-erasure.rego**: Detect prompts that reference deleted/erased data subjects. Block processing of data marked for erasure. Return block referencing Article 17.

    5. **dpia-required.rego**: Flag high-risk data processing activities. Detect profiling, large-scale processing, systematic monitoring. Return block referencing Article 35.

    **src/seed/run-seed.ts:**
    - Script executable via `bun run src/seed/run-seed.ts`
    - For each framework directory (`eu-ai-act`, `gdpr`):
      1. Read `framework.json`
      2. Check if framework already exists by slug (idempotent -- skip if exists)
      3. Insert framework record with `is_seeded = true`
      4. For each policy in the framework:

        b. Create a policy via direct DB insert (name format: `{framework_slug}/{policy_filename}`, e.g., `eu-ai-act/transparency-notice`)
        c. Insert first policy_version with the Rego source and entrypoint `interdict/policy/verdict`
        d. Insert framework_policy record linking the policy to the framework with requirement_ref and requirement_description
    - Add `"seed": "bun run src/seed/run-seed.ts"` script to package.json
    - Log progress for each framework and policy processed
    - Handle errors gracefully with rollback on framework-level transaction failure

    - Less common frameworks (Singapore PDPA, India DPDP, etc.) available as on-demand imports (future)
