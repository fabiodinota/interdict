    - Test: Updating a policy creates a new version (version increments), previous version remains accessible
    - Test: Getting version history returns all versions for a policy in descending order
    - Test: Restoring a previous version creates a new version with the old version's Rego source
    - Test: Deleting a policy soft-deletes (is_active = false) and its versions remain for audit
    - Test: OPA check validation catches invalid Rego syntax and returns structured errors
    - Test: Compilation worker writes Wasm to filesystem and updates DB with path, hash, and size
    - Test: Compilation failure updates status to 'failed' with error message
    - Test: Wasm module exceeding 1MB is rejected with descriptive error

  <action>
    **src/modules/policies/model.ts:**
    - TypeBox schemas for request/response validation:
      - `CreatePolicyBody`: name (string 1-255), description (string), rego_source (string, minLength 1), entrypoint (string, default 'interdict/policy/verdict')
      - `UpdatePolicyBody`: rego_source (string), entrypoint (optional string), change_description (optional string)
      - `PolicyResponse`: id, name, description, current_version (with version number, compilation_status, created_at), is_active
      - `PolicyVersionResponse`: id, version, rego_source, entrypoint, compilation_status, compilation_error, wasm_hash, wasm_size_bytes, created_at, change_description
      - `PolicyListQuery`: page_size (optional, default 50, max 200), cursor (optional)

    **src/modules/policies/service.ts (PolicyService):**
    - `create(body)`: Insert into `policies` table, insert first version into `policy_versions` (version=1), dispatch async compilation, return policy with version. Use a transaction.
    - `getById(id)`: Fetch policy with current version joined. Throw `NotFoundError` if not found or is_active=false.
    - `update(id, body)`: Fetch current max version number, insert new version (version+1), update `policies.current_version_id`, dispatch async compilation. Use a transaction.
    - `delete(id)`: Set is_active=false, updated_at=now(). Do NOT delete versions (audit compliance per CONTEXT.md).
    - `getVersionHistory(policyId)`: Query policy_versions for given policy_id ordered by version DESC.
    - `restoreVersion(policyId, versionId)`: Read the old version's rego_source and entrypoint, create a new version with that content (effectively a new edit), dispatch compilation.
    - `list(cursor?, pageSize?)`: Paginate active policies with cursor-based pagination on (updated_at, id).

    **src/modules/compiler/validator.ts:**
    - `validateRego(regoSource: string): Promise<ValidationResult>` -- Write Rego to temp file, run `opa check --strict --format json`, parse output. Return `{ valid: true }` or `{ valid: false, errors: [{ message, line?, column? }] }`.
    - Use `Bun.$` shell for subprocess execution with `.quiet().nothrow()`.
    - Clean up temp files in `finally` block.

    **src/modules/compiler/worker.ts:**
    - `compilePolicy(job: { policyVersionId, regoSource, entrypoint }): Promise<CompilationResult>` -- Writes Rego to temp dir, runs `opa build -t wasm -e {entrypoint} {path} -o {tmpDir}/bundle.tar.gz`, extracts `policy.wasm` from the tar.gz, checks size against 1MB limit (1_048_576 bytes per Pitfall 2), computes SHA-256 hash, writes to `{WASM_STORAGE_DIR}/{policyId}/{version}.wasm`, returns `{ success, wasmPath?, wasmHash?, wasmSizeBytes?, error? }`.
    - `startCompilationWorker(db)`: Background loop processing pending compilation jobs. On startup, check for any versions stuck in 'compiling' status (stale from previous crash) and reset to 'pending'. Poll `policy_versions WHERE compilation_status = 'pending'` every 2 seconds. For each pending version: set status to 'compiling', call `compilePolicy`, update status to 'compiled' or 'failed' with results.
    - Ensure `data/wasm/{policyId}/` directory is created before writing.
    - Per CONTEXT.md locked decision: compilation is asynchronous, save returns immediately with 'compiling' status.
    - Per CONTEXT.md locked decision: OPA CLI (`opa build`) for compilation.

    **src/modules/compiler/index.ts:**
    - Elysia plugin with `GET /api/v1/policies/:id/compilation-status` endpoint returning current compilation status and error details.

    **src/modules/policies/index.ts (policiesModule):**
    - Elysia plugin with prefix `/api/v1/policies`:
      - `POST /` -- create policy (validates body, pre-validates Rego via `validateRego`, creates policy+version, returns 201)
      - `GET /` -- list active policies with cursor pagination
      - `GET /:id` -- get policy by ID with current version
      - `PUT /:id` -- update policy (creates new version)
      - `DELETE /:id` -- soft-delete policy
      - `GET /:id/versions` -- get version history
      - `POST /:id/restore/:versionId` -- restore a previous version
    - Wire TypeBox validation schemas from model.ts on all routes.
    - Pre-validate Rego on create/update before saving. If Rego is invalid, return 400 with structured errors immediately (do not dispatch compilation).

    Wire `policiesModule` and `compilerModule` into the main Elysia app in `src/index.ts`. Start `startCompilationWorker(db)` on app startup.

      - `UpdateVendorBody`: display_name (optional), status (optional: 'approved' | 'blocked'), base_url (optional), description (optional)
      - `CreateModelBody`: model_name (string 1-255), status (optional: 'approved' | 'blocked', default 'approved')
      - `UpdateModelBody`: status ('approved' | 'blocked')
      - `VendorResponse`: id, name, display_name, status, base_url, models (array of model objects)
      - `VendorListQuery`: page_size (optional), cursor (optional), status (optional filter)

    **src/modules/vendors/service.ts (VendorService):**
    - `create(body)`: Insert vendor, return vendor object. Handle unique constraint violation as ConflictError.
    - `getById(id)`: Fetch vendor with models joined. Throw NotFoundError if not found.
    - `update(id, body)`: Update vendor fields. If status changes to 'blocked', also cascade-update all models to 'blocked'.
    - `delete(id)`: Hard delete (cascade deletes models -- vendor registry is not audit-sensitive like policies).
    - `list(cursor?, pageSize?, statusFilter?)`: Paginate vendors with their models.
    - `addModel(vendorId, body)`: Insert model. Handle duplicate (vendor_id, model_name) as ConflictError.
    - `updateModel(vendorId, modelId, body)`: Update model status.
    - `removeModel(vendorId, modelId)`: Delete model.
    - `listModels(vendorId)`: List models for a vendor.

      - `PUT /:id/models/:modelId` -- update model status
