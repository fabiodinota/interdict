  <action>
    Create the `control-plane/` directory at the project root (sibling to `crates/`).

    **package.json:**
    - Dependencies: `elysia`, `drizzle-orm`, `drizzle-typebox`, `postgres` (postgres.js), `@clickhouse/client`, `@sinclair/typebox`
    - Dev dependencies: `drizzle-kit`, `typescript`, `@types/bun`
    - Add `overrides` pinning `@sinclair/typebox` to `0.32.4` to match Elysia's internal version (avoids Pitfall 4 from research)
    - Scripts: `"dev": "bun run --hot src/index.ts"`, `"start": "bun run src/index.ts"`, `"db:generate": "drizzle-kit generate"`, `"db:migrate": "drizzle-kit migrate"`, `"db:studio": "drizzle-kit studio"`, `"test": "bun test"`

    **tsconfig.json:** Strict mode, target ES2022, module ESNext, moduleResolution bundler, paths alias `@/*` to `./src/*`.

    **bunfig.toml:** Minimal Bun config.

    **drizzle.config.ts:** Configure drizzle-kit with `dialect: "postgresql"`, schema path `./src/db/schema/*`, migrations output `./src/db/migrations`.

    **.env.example:**
    ```
    PORT=3000
    DATABASE_URL=postgres://interdict:interdict@localhost:5432/interdict
    CLICKHOUSE_URL=http://localhost:8123
    CLICKHOUSE_DATABASE=interdict
    WASM_STORAGE_DIR=./data/wasm
    OPA_BINARY_PATH=opa
    ```

    **config.ts:** Load and validate environment variables. Check for required vars. Check OPA binary exists in PATH at startup (`Bun.which('opa')`) -- warn if not found (Pitfall 1 from research). Export a typed Config object.

    **src/db/postgres.ts:**
    - Create postgres.js connection with explicit pool config (`max: 20`, idle timeout, connect timeout)
    - Initialize Drizzle ORM with all schemas imported from `./schema/index.ts`
    - Export `db` (Drizzle instance) and `queryClient` (raw postgres.js client for migrations)

    **src/db/clickhouse.ts:**
    - Create `@clickhouse/client` singleton using `createClient()` with URL from config
    - Use the Node.js variant (`@clickhouse/client` not `@clickhouse/client-web`)
    - Export `clickhouse` client instance
    - Do NOT create tables/views -- the evidence-collector manages ClickHouse schema

    **src/index.ts:**
    - Create Elysia app with `decorate('db', db)` and `decorate('clickhouse', clickhouse)`
    - Add health check route `GET /health` returning `{ status: "ok", timestamp: Date.now() }`
    - Add global `onError` handler mapping custom error classes to HTTP status codes and structured error responses
    - Listen on configured port
    - Log startup message with port number

    Run `cd control-plane && bun install` after creating package.json.

  <action>
    **src/db/schema/policies.ts:**
    - `compilationStatusEnum` pgEnum: 'pending', 'compiling', 'compiled', 'failed'
    - `policies` table: id (uuid PK), name (varchar 255 unique), description (text), current_version_id (uuid nullable FK to policy_versions), is_active (boolean default true), created_at, updated_at, created_by (uuid nullable -- enforced in Phase 7)
    - `policyVersions` table: id (uuid PK), policy_id (uuid FK to policies with cascade delete), version (integer, auto-incrementing per policy), rego_source (text not null), entrypoint (varchar 512 not null), compilation_status (enum default 'pending'), compilation_error (text nullable), wasm_path (varchar 1024 nullable -- filesystem path per discretion recommendation), wasm_hash (varchar 64 nullable -- SHA-256), wasm_size_bytes (integer nullable), created_at, created_by (uuid nullable), change_description (text nullable)
    - Add unique index on (policy_id, version)
    - Per CONTEXT.md locked decision: full version history, every edit creates new version, previous versions queryable and restorable

    **src/db/schema/vendors.ts:**
    - `vendors` table: id (uuid PK), name (varchar 255 unique not null), display_name (varchar 255 not null), status (varchar 20 default 'approved' -- 'approved' | 'blocked'), base_url (varchar 1024 nullable), description (text nullable), created_at, updated_at
    - `vendorModels` table: id (uuid PK), vendor_id (uuid FK to vendors with cascade delete), model_name (varchar 255 not null), status (varchar 20 default 'approved'), created_at, updated_at
    - Unique index on (vendor_id, model_name) per CONTEXT.md locked decision: per-vendor model version control

    **src/db/schema/regulatory.ts:**
    - `frameworks` table: id (uuid PK), slug (varchar 100 unique not null -- e.g., 'eu-ai-act', 'gdpr'), name (varchar 255 not null), description (text), jurisdiction (varchar 100), version (varchar 50), is_seeded (boolean default false -- indicates built-in vs custom), created_at, updated_at
    - `frameworkPolicies` table: id (uuid PK), framework_id (uuid FK to frameworks), policy_id (uuid FK to policies), requirement_ref (varchar 255 -- e.g., 'Article 14.1'), requirement_description (text), is_required (boolean default true), sort_order (integer default 0), created_at
    - Unique index on (framework_id, policy_id)
    - `frameworkActivations` table: id (uuid PK), framework_id (uuid FK to frameworks), activated_by (uuid nullable -- FK to users), is_active (boolean default true), activated_at (timestamp default now), deactivated_at (timestamp nullable)
    - Per CONTEXT.md: enabling a framework is additive, individual policies can be toggled off

    **src/db/schema/organization.ts:**
    - `departments` table: id (uuid PK), name (varchar 255 unique not null), display_name (varchar 255 not null), parent_department_id (uuid nullable self-referencing FK), created_at, updated_at
    - `teams` table: id (uuid PK), name (varchar 255 not null), department_id (uuid FK to departments), created_at, updated_at. Unique index on (department_id, name)
    - `users` table: id (uuid PK), email (varchar 255 unique not null), display_name (varchar 255 not null), department_id (uuid nullable FK to departments), team_id (uuid nullable FK to teams), external_id (varchar 255 nullable -- SAML subject, Phase 7), role (varchar 50 default 'read_only_auditor'), is_active (boolean default true), created_at, updated_at
    - Note: RBAC enforcement deferred to Phase 7; schema includes role column for forward compatibility

    **src/db/schema/index.ts:** Re-export all tables and enums from the four schema files.

    **src/shared/errors.ts:**
    - `AppError` base class extending Error with `statusCode` and `code` properties
    - `NotFoundError` (404, 'NOT_FOUND')
    - `ValidationError` (400, 'VALIDATION_ERROR') with optional `details` field
    - `CompilationError` (422, 'COMPILATION_ERROR') with optional `details` field
    - `ConflictError` (409, 'CONFLICT') for duplicate names etc.

    **src/shared/response.ts:**
    - `apiResponse<T>(data: T, meta?: Record<string, unknown>)` returns `{ success: true, data, meta }`
    - `paginatedResponse<T>(items: T[], nextCursor: string | null, total?: number)` returns `{ success: true, data, pagination: { nextCursor, hasMore, total? } }`
    - `apiError(code: string, message: string, details?: unknown)` returns `{ success: false, error: { code, message, details } }`

    **src/shared/pagination.ts:**
    - `encodeCursor(timestamp: number, id: string): string` -- Base64url encode `${timestamp}|${id}`
    - `decodeCursor(cursor: string): { timestamp: number, id: string }` -- Decode and parse
    - `DEFAULT_PAGE_SIZE = 50`
    - `MAX_PAGE_SIZE = 200`

    After creating schemas, run `cd control-plane && bun run db:generate` to generate the initial migration SQL. Then verify the TypeScript compiles with `bun build --target=bun src/index.ts --outdir=./dist`.
