**queries.ts:** Four ClickHouse query functions. ALL queries MUST include `event_date` partition filter. Use parameterized queries with `query_params`.

1. `queryVolumeAnomalies(client, thresholdRatio)` -- Compare current hour request count per actor_identity against 7-day same-hour average. Use the CTE pattern from RESEARCH.md:
   - Baseline: avg and stddevPop of hourly counts for same hour-of-day over past 7 days (event_date >= today() - 7 AND event_date < today(), toHour(timestamp) = toHour(now()))
   - Current: count per actor in current hour (event_date = today(), timestamp >= toStartOfHour(now()))
   - Return rows where current_count > baseline_avg * thresholdRatio (default 1.2)
   - Return: actor_identity, current_count, baseline_avg, baseline_std, ratio

2. `queryOffHoursUsage(client, businessStart, businessEnd)` -- Find users with requests outside business hours who historically work in-hours:
   - Current window: last 24 hours, filter for toHour(timestamp) < businessStart OR toHour(timestamp) >= businessEnd (default 6-22)
   - Baseline: same user's ratio of off-hours to total over past 30 days
   - Flag users whose current off-hours ratio significantly exceeds their baseline
   - event_date filter: >= today() - 30 AND <= today()
   - Return: actor_identity, off_hours_count, total_count, historical_off_hours_pct, current_off_hours_pct

3. `queryVendorSwitching(client)` -- Find users who switched to a different vendor than their dominant one:
   - Baseline: per user, the vendor handling >80% of their requests over past 30 days
   - Current: last 24 hours, any requests to a non-dominant vendor
   - event_date filter: >= today() - 30 AND <= today()
   - Return: actor_identity, dominant_vendor, current_vendor, dominant_pct, switch_count

4. `queryTopicDrift(client)` -- Prompt hash entropy as proxy for topic drift (per Open Question #3 in RESEARCH.md):
   - Baseline: per user, average unique prompt hashes per hour over past 7 days
   - Current: unique prompt hashes in current hour
   - Flag users whose unique hash count significantly exceeds baseline
   - event_date filter: >= today() - 7 AND <= today()
   - Return: actor_identity, current_unique_hashes, baseline_avg_unique, ratio
   - IMPORTANT: Never return prompt_hash values in the response (Invariant #6). Only return counts.

**service.ts:** Create `AnomalyService`:

1. `detectAnomalies(departmentIds?: string[])` -- Run all four query functions. For each result row, compute severity:
   - Info: ratio >= 1.2x and < 2x (or off-hours/switch detected but mild)
   - Warning: ratio >= 2x and < 5x
   - Critical: ratio >= 5x OR multi-factor (e.g., off-hours + high volume)

2. Generate human-readable `summary` strings: "Normal: 50 requests/hour, Observed: 200 requests/hour" format per CONTEXT.md decision.

3. Generate `actions` array with quick-links:
   - Volume spike: `{ label: "View audit trail", href: "/audit?actor={actorIdentity}" }`
   - Off-hours: `{ label: "View audit trail", href: "/audit?actor={actorIdentity}&from_date={...}" }`
   - Vendor switch: `{ label: "Investigate vendor usage", href: "/vendors" }`
   - Topic drift: `{ label: "Review department policies", href: "/department-policies" }`

4. Sort results by severity (critical first) then by ratio descending.

5. Optional department filtering: if departmentIds provided, add department filter to queries (WHERE department IN ...).
