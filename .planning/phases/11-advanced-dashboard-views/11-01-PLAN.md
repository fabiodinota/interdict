**model.ts:** Define TypeBox schemas for:
- POST /verify request: `{ bundle_ids: string[] }` (max 100)
- GET /bundles: query params for listing bundles with pagination (cursor, page_size, from_date, to_date)
- VerificationResult response type matching the interface from RESEARCH.md

**service.ts:** Create `EvidenceVerificationService` class taking ClickHouse client and Drizzle DB:

1. `listBundles(filters, cursor, pageSize, departmentIds)` -- query ClickHouse evidence_bundles with department scoping, return paginated list with bundle_id, chain_hash, timestamp, signing_key_id, actor_identity, vendor, policy_action

2. `verifyBundles(bundleIds: string[])` -- for each bundle:
   - **Hash chain check:** Query ClickHouse for the bundle AND its predecessor (same kernel_id, sequence_number - 1). Verify that `chain_hash[n]` links correctly to `previous_hash[n]` matching `chain_hash[n-1]`. This is a chain linkage verification (not content re-hashing per Open Question #1 in RESEARCH.md -- chain linkage is reliable without reconstructing exact bundle content bytes).
   - **Signature check:** Look up `signing_key_id` in Postgres `signing_keys` table to get `publicKeyHex`. Use Bun's `crypto.subtle.verify("Ed25519", publicKey, signatureBytes, bundleContentBytes)` if available. If Bun WebCrypto Ed25519 is not supported, install and use `@noble/ed25519`. For signature verification, use the `chain_hash` bytes as the signed message (this is what the evidence collector signs per the signing module pattern).
   - **Merkle proof check:** Return `{ passed: null, reason: "Merkle root storage not yet available" }` for now. Per Open Question #2, Merkle roots are only in S3 and the control plane lacks S3 access. Flag as partial verification -- a future enhancement can add a `merkle_anchors` Postgres table.

3. Return `VerificationResult[]` with per-step pass/fail and detail fields (expected hash, actual hash, key ID, public key hex, signature hex).

**index.ts:** Elysia plugin at prefix `/api/v1/evidence`:
- `POST /verify` -- accepts `{ bundle_ids }`, calls verifyBundles, returns results. Auth: `read_only_auditor` minimum.
- `GET /bundles` -- lists evidence bundles with pagination and department scoping. Auth: `read_only_auditor` minimum.
