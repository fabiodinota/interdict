**schema/reviews.ts:** Create `review_items` table per the RESEARCH.md pattern:
```typescript
export const reviewItems = pgTable("review_items", {
  id: uuid("id").primaryKey().defaultRandom(),
  bundleId: varchar("bundle_id", { length: 255 }).notNull(),
  escalatedAt: timestamp("escalated_at").notNull(),
  slaDeadline: timestamp("sla_deadline").notNull(),
  status: varchar("status", { length: 20 }).notNull().default("pending"),
    // pending | claimed | approved | rejected | auto_escalated
  claimedBy: uuid("claimed_by").references(() => users.id),
  claimedAt: timestamp("claimed_at"),
  resolvedBy: uuid("resolved_by").references(() => users.id),
  resolvedAt: timestamp("resolved_at"),
  resolution: varchar("resolution", { length: 50 }),
    // false_positive | violation_confirmed | needs_policy_update | insufficient_context
  resolutionNotes: text("resolution_notes"),
  autoEscalatedTo: uuid("auto_escalated_to").references(() => users.id),
  createdAt: timestamp("created_at").defaultNow().notNull(),
  updatedAt: timestamp("updated_at").defaultNow().notNull(),
});
```
Add index on `status` and `sla_deadline` for queue sorting.

**model.ts:** TypeBox schemas for:
- GET /queue query params: `status` filter (pending|claimed|all), cursor, page_size
- POST /:id/claim -- no body needed
- POST /:id/resolve: `{ resolution: string, resolution_notes: string }` where resolution is one of the four categories
- Review item response shape

**service.ts:** Create `ReviewService` class:

1. `getQueue(statusFilter, cursor, pageSize)` -- Query review_items sorted by sla_deadline ASC (most urgent first). For each item, also query ClickHouse for the associated evidence bundle details (actor, vendor, model, policy rules, risk score, prompt_hash, response_hash).

2. `claimReview(reviewId, userId)` -- Optimistic lock: `UPDATE review_items SET claimed_by=$1, claimed_at=NOW(), status='claimed' WHERE id=$2 AND status='pending' RETURNING *`. Return null if 0 rows (already claimed).

3. `resolveReview(reviewId, userId, resolution, notes)` -- Update to approved/rejected: `UPDATE review_items SET resolved_by=$1, resolved_at=NOW(), status=$resolution, resolution=$3, resolution_notes=$4 WHERE id=$2 AND (claimed_by=$1 OR status='pending') RETURNING *`. Validate resolution is one of the four allowed categories.

4. `syncEscalations()` -- Background job: Query ClickHouse for `policy_action = 'escalate'` bundles from the last hour that do NOT have a matching `review_items` row (LEFT JOIN or NOT IN check). Create new review_items with `sla_deadline = escalated_at + 4 hours`. Call this on a 60-second `setInterval` registered at module startup.

5. `autoEscalateExpired()` -- Background job: `UPDATE review_items SET status='auto_escalated' WHERE status='pending' AND sla_deadline < NOW()`. Run on the same 60-second interval.

**index.ts:** Elysia plugin at prefix `/api/v1/reviews`:
- `GET /queue` -- returns paginated queue. Auth: `compliance_officer` minimum.
- `POST /:id/claim` -- claims item. Auth: `compliance_officer` minimum. Returns 409 if already claimed.
- `POST /:id/resolve` -- resolves item. Auth: `compliance_officer` minimum. Validates mandatory resolution + notes.
- `GET /:id` -- returns single review item with full bundle details from ClickHouse.

Register background jobs (syncEscalations + autoEscalateExpired) in the module's `.onStart()` or via setInterval in the derive block.

**use-reviews.ts:** TanStack Query hooks:
- `useReviewQueue(statusFilter, cursor, pageSize)` -- GET /reviews/queue with 30s refetchInterval (keeps SLA timers fresh). Use keepPreviousData.
- `useClaimReview()` -- useMutation POST /reviews/:id/claim. On success, invalidate review queue query. On 409 error, show toast "Item already claimed by another reviewer".
- `useResolveReview()` -- useMutation POST /reviews/:id/resolve with `{ resolution, resolution_notes }`. On success, invalidate queue and show success toast.
- `useReviewDetail(id)` -- GET /reviews/:id for single item detail.

**SlaTimer.tsx:** Component taking `deadline: string` (ISO UTC timestamp):
- Calculate remaining seconds using `differenceInSeconds(new Date(deadline), new Date())` from date-fns
- Use a local `useState` + `useEffect` with 1-second setInterval to update countdown display (separate from TanStack Query refetch which handles data freshness)
- Display format: "Xh Ym" or "Xm Ys" when under 1 hour
- Color logic: remaining/total > 0.25 = default (gray badge), remaining/total <= 0.25 = "warning" (yellow/amber bg), remaining <= 0 = "destructive" (red badge with "EXPIRED")
- Total SLA = 4 hours (14400 seconds)
- Clean up interval on unmount

**ReviewQueue.tsx:** TanStack Table component:
- Status filter tabs at top: "Pending" (default), "Claimed", "All"

- Actions column: "Review" button (if pending) triggers claim mutation then opens ReviewDialog. If claimed by current user, shows "Continue Review". If claimed by someone else, shows "Claimed" disabled.
- Sort by SLA deadline ascending (most urgent first) -- server-side sort
- Cursor pagination at bottom
