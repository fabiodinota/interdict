    1. **Create `control-plane/src/db/schema/auth.ts`** with three Drizzle table definitions:

    **`apiKeys` table:**
    - `id`: uuid PK, defaultRandom
    - `userId`: uuid FK to users.id (onDelete cascade), NOT NULL
    - `keyHash`: varchar(64), NOT NULL, unique — SHA-256 hex digest
    - `keyPrefix`: varchar(16), NOT NULL — "ik_live_XXXXXXXX" for display/identification
    - `label`: varchar(255), nullable — user-provided label (e.g., "CI pipeline")
    - `isActive`: boolean, default true, NOT NULL
    - `lastUsedAt`: timestamp, nullable
    - `createdAt`: timestamp, defaultNow, NOT NULL
    - `revokedAt`: timestamp, nullable
    - Indexes: unique index on `keyHash`, index on `userId`

    **`userDepartments` join table:**
    - `userId`: uuid FK to users.id (onDelete cascade), NOT NULL
    - `departmentId`: uuid FK to departments.id (onDelete cascade), NOT NULL
    - `createdAt`: timestamp, defaultNow, NOT NULL
    - Composite PK on (userId, departmentId)

    **`rolePermissions` table:**
    - `id`: uuid PK, defaultRandom
    - `role`: varchar(50), NOT NULL
    - `permission`: varchar(100), NOT NULL
    - `isGranted`: boolean, default true, NOT NULL
    - `createdAt`: timestamp, defaultNow, NOT NULL
    - Unique index on (role, permission) pair

    2. **Modify `control-plane/src/db/schema/organization.ts`:**
    Add `isService` boolean column to `users` table: `isService: boolean("is_service").notNull().default(false)`. This distinguishes service accounts from human users. Do NOT remove any existing columns.

    3. **Modify `control-plane/src/db/schema/index.ts`:**
    Add re-export line: `export { apiKeys, userDepartments, rolePermissions } from "./auth";`

    4. **Create `control-plane/src/modules/auth/permissions.ts`:**

    Define the permission model per CONTEXT.md locked decisions:
    - `ROLE_HIERARCHY` record mapping role strings to numeric levels (read_only_auditor=1, department_manager=2, policy_admin=3, compliance_officer=4, super_admin=5)
    - `PERMISSIONS` string enum/constants for all permission strings: `audit:read`, `stats:read`, `policies:read`, `policies:write`, `vendors:read`, `vendors:write`, `regulatory:read`, `regulatory:write`, `reports:generate`, `reviews:manage`, `department:manage`, `users:read`, `users:write`, `api_keys:manage`
    - `DEFAULT_PERMISSIONS` record mapping each role to its permission array. Super Admin gets `["*"]` wildcard. Each lower role gets its appropriate subset. Permissions DO NOT inherit automatically via the map — the hierarchy is only for role-level comparisons (e.g., "does this user have at least Policy Admin access?"). Individual permissions are looked up directly.
    - `roleHierarchyLevel(role: string): number` — returns numeric level, 0 for unknown roles
    - `roleInheritsFrom(userRole: string, requiredRole: string): boolean` — returns true if userRole level >= requiredRole level
    - `hasPermission(role: string, permission: string, customPermissions?: Map<string, string[]>): boolean` — checks customPermissions first, falls back to DEFAULT_PERMISSIONS. Wildcard `"*"` grants everything.

    5. **Create `control-plane/src/modules/auth/permissions.test.ts`:**
    Unit tests for hierarchy level checks, permission checks, wildcard behavior, unknown role handling, custom permission override. Follow TDD: write tests first, then verify the implementation satisfies them.
