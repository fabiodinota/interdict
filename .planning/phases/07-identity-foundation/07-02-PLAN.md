    1. **Create `control-plane/src/modules/auth/middleware.ts`:** Elysia auth macro plugin.

    Per CONTEXT.md locked decision: use Elysia `macro` with `resolve` pattern (NOT `beforeHandle` or `derive`).

    ```typescript
    export const authPlugin = new Elysia({ name: "auth" })
      .macro({
        auth: (options?: string[] | boolean) => ({
          async resolve({ headers, status, store }) {
            // 1. Extract Bearer token from Authorization header
            const authHeader = headers["authorization"];
            if (!authHeader?.startsWith("Bearer ")) {
              return status(401, {
                success: false,
                error: { code: "UNAUTHORIZED", message: "Missing or invalid Authorization header" },
              });
            }

            const token = authHeader.slice(7);

            // 2. Validate API key via auth service
            const authService = createAuthService((store as any).db);
            const user = await authService.authenticateByApiKey(token);

            if (!user) {
              return status(401, {
                success: false,
                error: { code: "UNAUTHORIZED", message: "Invalid API key" },
              });
            }

            // 3. Role check if required roles specified
            if (Array.isArray(options) && options.length > 0) {
              const minRequiredLevel = Math.min(
                ...options.map(roleHierarchyLevel)
              );
              if (roleHierarchyLevel(user.role) < minRequiredLevel) {
                return status(403, {
                  success: false,
                  error: { code: "FORBIDDEN", message: "Insufficient role permissions" },
                });
              }
            }

            // 4. Return user to context — available as `user` in route handlers
            return { user };
          },
        }),
      });
    ```

    The macro allows per-route configuration:
    - `{ auth: true }` — requires any authenticated user
    - `{ auth: ["policy_admin"] }` — requires Policy Admin or higher (by hierarchy)
    - `{ auth: ["super_admin"] }` — requires Super Admin only
    - No `auth` option — route is public (health check, etc.)

    **Important:** Do NOT create the auth service instance at plugin level. Create it inside `resolve` using `store.db` to ensure it uses the decorated DB instance. This follows the existing pattern in `policiesModule` and `auditModule`.

    **CRITICAL:** Never include the API key token value in error responses or log output. Return generic error messages only.

    b. **`POST /api/v1/auth/keys`** — `{ auth: true }`
    Create a new API key for the authenticated user. Body: `{ label?: string }`.
    Returns `{ id, plaintext, prefix, label, created_at }`. The `plaintext` field is shown exactly once.
    Use `authService.createApiKey(user.id, body.label)`.

    c. **`GET /api/v1/auth/keys`** — `{ auth: true }`
    List API keys for the authenticated user. Super Admins can see all keys via query param `?all=true`.
    Returns paginated list of `{ id, prefix, label, is_active, last_used_at, created_at }`.
