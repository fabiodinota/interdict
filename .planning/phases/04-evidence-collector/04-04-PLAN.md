**User decisions to honor:**
- Three verification modes: single bundle, time-range chain, full chain integrity check
- Default output: human-readable summary with pass/fail per check
- `--json` flag for machine-parseable output
- Export-based offline verification: reads exported protobuf bundle files from disk
- Standalone binary with zero runtime dependencies (user decision: clean trust boundary)

**1. Create `crates/interdict-verify/src/chain.rs`:**
Hash chain verification:
- `verify_chain(bundles: &[EvidenceBundle]) -> ChainVerificationResult`:
  - Sort bundles by (kernel_id, sequence_number)
  - Group by kernel_id (per-kernel independent chains per Pitfall 2)
  - For each kernel's chain:
    - Verify sequence numbers are contiguous (no gaps)
    - Verify each bundle's chain_hash == SHA-256(previous_hash || bundle_content_bytes)
    - The first bundle's previous_hash should be all zeros (genesis)
  - Return per-kernel results with:
    - `valid: bool`
    - `bundles_checked: usize`
    - `first_invalid_sequence: Option<u64>` (if chain breaks)
    - `error_detail: Option<String>`
- `verify_single_bundle(bundle: &EvidenceBundle, expected_previous: &[u8; 32]) -> bool`:
  - Recompute SHA-256(expected_previous || bundle_content) and compare to bundle.chain_hash
- Unit tests:
  - Valid chain of 5 bundles passes
  - Tampered bundle (modified content) fails with correct sequence identified
  - Gap in sequence numbers detected
  - Multiple kernels verified independently

**2. Create `crates/interdict-verify/src/signature.rs`:**
Ed25519 signature verification:
- `verify_signature(bundle: &EvidenceBundle, public_key: &[u8]) -> SignatureVerificationResult`:
  - Parse public key as `ed25519_dalek::VerifyingKey`
  - Parse signature as `ed25519_dalek::Signature`
  - Verify signature against the bundle content bytes (same bytes that were signed)
  - Return `valid: bool`, `key_id: String`, `dev_signed: bool`
- `verify_bundle_signatures(bundles: &[EvidenceBundle], public_keys: &HashMap<String, Vec<u8>>) -> Vec<SignatureVerificationResult>`:
  - Look up public key by bundle's `signing_key_id`
  - Verify each bundle's signature
  - Return results with any failures flagged
- Public keys provided as a key file (JSON map of key_id -> hex-encoded public key)
- Unit tests:
  - Valid signature passes
  - Tampered bundle fails signature check
  - Missing public key returns error (not panic)
  - Dev-signed flag is reported correctly

**3. Create `crates/interdict-verify/src/merkle.rs`:**
Merkle root verification:
- `verify_merkle_root(bundles: &[EvidenceBundle], expected_root: &[u8; 32]) -> MerkleVerificationResult`:
  - Extract chain_hash from each bundle as leaf
  - Build Merkle tree using `rs_merkle::MerkleTree::<Sha256>::from_leaves()`
  - Compare computed root to expected_root
  - Return `valid: bool`, `computed_root: String` (hex), `expected_root: String` (hex), `leaf_count: usize`
- `verify_against_s3_anchor(anchor_file: &Path) -> Result<MerkleAnchor>`:
  - Read the S3 anchor JSON file (exported to local disk per user decision: offline verification)
  - Parse hour, merkle_root (hex), bundle_count, anchored_at
  - Return the parsed anchor for comparison
- Unit tests:
  - Correct bundles produce matching Merkle root
  - Modified bundle changes root (detected)
  - Empty bundle list returns appropriate result
  - S3 anchor JSON parsing works

**4. Create `crates/interdict-verify/src/report.rs`:**
Verification report formatting:
- `VerificationReport` struct aggregating chain, signature, and Merkle results
- `format_human(report: &VerificationReport) -> String`:
  - Human-readable summary with checkmarks/crosses per check
  - Example output:
    ```
    Evidence Verification Report
    ============================
    Chain Integrity:    PASS (1,234 bundles across 3 kernels)
    Ed25519 Signatures: PASS (1,234/1,234 valid)
    Merkle Root:        PASS (matches S3 anchor for 2026-02-28T14:00:00Z)

    Overall: PASS
    ```
  - On failure, include detail: which sequence number, which kernel, what mismatch
- `format_json(report: &VerificationReport) -> String`:
  - Machine-parseable JSON with all fields for CI pipelines (user decision)
  - Includes `overall_valid`, `chain`, `signatures`, `merkle` sections
- Unit tests:
  - Human format includes PASS/FAIL
  - JSON format is valid JSON

**5. Update `crates/interdict-verify/src/main.rs`:**
Replace the placeholder subcommand implementations with real logic:
- `verify bundle <file> --public-keys <key_file>`:
  - Read single protobuf bundle file
  - Verify signature using provided public key
  - Output report
- `verify range <dir> --from <time> --to <time> --public-keys <key_file> [--anchor-dir <dir>]`:
  - Read all protobuf bundle files in directory within time range
  - Verify chain integrity for bundles in range
  - Verify signatures
  - If --anchor-dir provided, verify Merkle roots against exported S3 anchor JSON files
  - Output report
- `verify chain <dir> --public-keys <key_file> [--anchor-dir <dir>]`:
  - Read ALL protobuf bundle files in directory
  - Full chain integrity check (all kernels, all sequences)
  - Verify all signatures
  - If --anchor-dir provided, verify all Merkle roots
  - Output report
- All commands support `--json` flag and `--kernel-id` filter
- Exit code: 0 for PASS, 1 for FAIL, 2 for errors

**Create `crates/evidence-collector/tests/integration_test.rs`:**

Since ClickHouse and S3 are external services not available in CI without Docker, the integration tests focus on the in-process components that can be tested without external dependencies:

**Test 1: `test_chain_integrity_roundtrip`**
- Create a `ChainManager` and `LocalSigningProvider`
- Generate 100 evidence bundles with sequential content
- For each bundle: compute chain hash via ChainManager, sign with provider
- Export bundles as protobuf bytes
- Use interdict-verify's chain verification to validate the entire chain
- Tamper with one bundle's content bytes (modify a field)
- Re-run verification and assert it detects the tamper at the correct sequence
- This proves EVID-02 (hash chain) + EVID-03 (signing) + EVID-10 (verification) end-to-end

**Test 2: `test_merkle_tree_construction_and_verification`**
- Create a `HourlyMerkleBuilder`
- Add 50 bundle hashes
- Finalize and get MerkleAnchor
- Serialize anchor to JSON (simulating S3 export)
- Use interdict-verify's Merkle verification to validate root matches
- Modify one leaf hash and rebuild -- verify root changes (tamper detection)
- This proves EVID-04 (Merkle tree) + EVID-10 (verification)

**Test 3: `test_evidence_buffer_nonblocking`**
- Create `EvidenceBuffer` with a disconnected/stub collector
- Measure time to `try_send` 10,000 events
- Assert total time < 10ms (proving non-blocking behavior -- KERN-14)
- Fill buffer to capacity, send one more, assert it returns without blocking
- This proves KERN-14 (async, no latency impact)

**Test 4: `test_evidence_bundle_schema_completeness`**
- Create a `RawEvidenceEvent` with all fields populated
- Convert to protobuf `EvidenceBundle`
- Serialize and deserialize
- Assert all EVID-06 fields survive the roundtrip:
  - actor_identity, department, vendor, model
  - prompt_hash, response_hash
  - policy_action, policy_rules_json
  - token_count, enforcement_latency_us
  - schema_version == 1
- This proves EVID-06 (complete schema)

**Test 5: `test_signing_provider_dev_mode`**
- Generate ephemeral keypair with LocalSigningProvider
- Sign a message
- Verify signature passes with the provider's public key
- Assert `is_dev_key()` returns true
- Assert `key_id()` is a valid hex string
- Serialize public key, create new VerifyingKey, verify again
- This proves EVID-09 (dev mode signing)

**Test 6: `test_clickhouse_row_serialization`**
- Create an `EvidenceRow` with all fields
- Serialize to the format expected by clickhouse crate
- Verify field names and types match the ClickHouse schema DDL
- This proves EVID-07 compatibility (rows can be inserted)

**Test 7: `test_multiple_kernel_chains_independent`**
- Create ChainManager
- Interleave bundles from 3 different kernel_ids
- Verify each kernel's chain is independently valid
- Verify modifying one kernel's bundle doesn't affect other kernels' chains
- This proves Pitfall 2 mitigation (per-kernel chains)
