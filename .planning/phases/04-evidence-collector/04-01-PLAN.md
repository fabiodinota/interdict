**2. Create `crates/evidence-collector/src/chain/hasher.rs`:**
Implement `ChainState` following 04-RESEARCH.md Pattern 2 (lines 247-282):
- `ChainState` struct with `previous_hash: [u8; 32]` and `sequence_number: u64`
- `ChainState::new()` initializes with zero hash (genesis block) and sequence 0
- `ChainState::link(&mut self, bundle_content: &[u8]) -> ([u8; 32], u64)` computes `SHA-256(previous_hash || bundle_content)`, updates internal state, increments sequence number
- Per Pitfall 2 (chain hash ordering): one ChainState per kernel_id. Add a `ChainManager` that wraps `HashMap<String, ChainState>` to maintain per-kernel chains. `ChainManager::link(kernel_id: &str, content: &[u8])` returns the hash and sequence for that kernel's chain.
- Unit tests:
  - Genesis block has zero previous hash
  - Two sequential bundles form a verifiable chain
  - Tampering with a bundle breaks the chain (re-compute and compare)
  - Different kernel_ids maintain independent chains

**4. Create `crates/evidence-collector/src/signing/mod.rs`:**
Define the `SigningProvider` trait following 04-RESEARCH.md Pattern 4 (lines 329-364):
```rust
use async_trait::async_trait;

#[async_trait]
pub trait SigningProvider: Send + Sync {
    async fn sign(&self, message: &[u8]) -> Result<Vec<u8>, SigningError>;
    fn public_key(&self) -> &[u8];
    fn key_id(&self) -> &str;
    fn is_dev_key(&self) -> bool;
}
```
Define `SigningError` with `thiserror`:
- `KmsError(String)` -- AWS KMS failures
- `LocalKeyError(String)` -- Local key operation failures

Export `LocalSigningProvider` and `KmsSigningProvider`.

**5. Create `crates/evidence-collector/src/signing/local.rs`:**
Implement `LocalSigningProvider` for dev/test mode (user decision: auto-generate ephemeral Ed25519 keypairs at startup, no KMS dependency for local development):
- `LocalSigningProvider::generate() -> Self` -- generates random Ed25519 keypair using `ed25519_dalek::SigningKey` with `rand::rngs::OsRng`
- `LocalSigningProvider::from_file(path: &Path) -> Result<Self>` -- loads from PEM/raw file for file-based air-gapped mode
- `is_dev_key()` returns `true` for generated keys, `false` for file-loaded
- `key_id()` returns a hex-encoded hash of the public key (first 16 bytes of SHA-256 of public key)
- Use `zeroize` feature -- SigningKey is automatically zeroized on drop (ed25519-dalek 2.x default)
- CRITICAL: Never implement Display/Debug for SigningKey (Pitfall 4: key material leakage)
- Unit tests:
  - Generate keypair, sign message, verify with public key
  - Different messages produce different signatures
  - Signature verification fails with wrong public key
