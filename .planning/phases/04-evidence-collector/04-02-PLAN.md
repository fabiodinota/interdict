<objective>
Implement the Evidence Collector gRPC service, ClickHouse batched storage, hourly Merkle tree construction with S3 WORM anchoring, and wire everything into the collector main binary.

Purpose: This is the core evidence pipeline -- receiving compressed evidence from kernels, computing chain hashes, persisting to ClickHouse with correct batching, and building hourly Merkle trees anchored to S3 for external immutability verification. The ClickHouse batching (min 1000 rows, max 1 INSERT/sec) is a correctness requirement to avoid "too many parts" failures.

Output: Fully functional evidence collector binary that receives gRPC streams, persists to ClickHouse, and anchors hourly Merkle roots to S3.
</objective>

**2. Create `crates/evidence-collector/src/grpc/service.rs`:**
Implement the `EvidenceCollector` gRPC service (EVID-01):
- Use the generated tonic server trait from the proto compilation
- Implement `submit_evidence` as a client-streaming RPC
- For each incoming `EvidenceBatch`:
  1. Decompress `compressed_payload` with `zstd::decode_all()` (user decision: zstd compression)
  2. Deserialize the decompressed bytes into `Vec<EvidenceBundle>` using prost
  3. For each bundle, call `ChainManager::link(kernel_id, &bundle_content_bytes)` to compute chain hash and sequence
  4. Call `chain::signer::sign_bundle(&signing_provider, &bundle_bytes)` to get Ed25519 signature
  5. Enqueue the signed, chain-linked bundle into `ClickHouseWriter` for batched persistence
  6. Add the bundle's chain_hash to the `HourlyMerkleBuilder` for Merkle tree construction
- Return `SubmitResponse` with accepted/rejected counts
- Hold `Arc<ChainManager>`, `Arc<dyn SigningProvider>`, `Arc<ClickHouseWriter>`, `Arc<Mutex<HourlyMerkleBuilder>>` as service state
- Per anti-pattern: do NOT block chain hash computation on ClickHouse writes. Compute chain hash inline (fast), queue for ClickHouse asynchronously.
- Log bundle acceptance/rejection with tracing (never log prompt/response content per CLAUDE.md rule 6)

**2. Create `crates/evidence-collector/src/merkle/builder.rs`:**
Implement `HourlyMerkleBuilder` following 04-RESEARCH.md Pattern 5 (lines 366-402):
- `HourlyMerkleBuilder` struct with:
  - `leaf_hashes: Vec<[u8; 32]>` -- accumulated bundle chain hashes
  - `hour_start: chrono::DateTime<chrono::Utc>` -- current window start
  - `max_leaves: usize` -- from config (default 1_000_000 -- Pitfall 6)
- `HourlyMerkleBuilder::new(hour_start, max_leaves) -> Self`
- `HourlyMerkleBuilder::add_bundle_hash(&mut self, hash: [u8; 32]) -> bool`:
  - Push hash to leaf_hashes
  - Return false if max_leaves exceeded (triggers sub-hourly checkpoint per Pitfall 6)
- `HourlyMerkleBuilder::finalize(&self) -> Option<MerkleAnchor>`:
  - If no leaves, return None (empty window -- skip anchoring per Pitfall 6)
  - Build `MerkleTree::<Sha256>::from_leaves(&self.leaf_hashes)` using rs_merkle
  - Return `MerkleAnchor { root: tree.root()?, bundle_count: self.leaf_hashes.len(), hour: self.hour_start }`
- `HourlyMerkleBuilder::reset(&mut self, new_hour: DateTime<Utc>)` -- clears leaves, updates hour_start
- `MerkleAnchor` struct with `root: [u8; 32]`, `bundle_count: usize`, `hour: DateTime<Utc>`

Add a background task function `merkle_rotation_task`:
- Runs on a `tokio::time::interval` aligned to hour boundaries
- When the hour ticks over:
  1. Calls `finalize()` on the current builder
  2. If Some(anchor), calls `anchor_merkle_root()` on S3
  3. Calls `reset()` with the new hour
  4. If `add_bundle_hash` returned false (max leaves exceeded), trigger immediate sub-hourly finalize+anchor

- Unit tests:
  - Empty tree returns None
  - Single leaf produces a valid root
  - Multiple leaves produce consistent root (deterministic)
  - Finalize + reset produces different trees for different hours
  - Max leaves triggers overflow detection

  - GET the anchor file and deserialize for verification
- Skip S3 operations in dev mode (no bucket configured) -- log warning and continue

- Unit test: S3 key format is correct for a given timestamp
