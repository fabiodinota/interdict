<objective>
Add the kernel-side evidence buffer with bounded async channel, background 500ms gRPC flusher, and evidence bundle construction from policy pipeline results.

Purpose: The kernel must create evidence bundles asynchronously without adding latency to proxied AI responses (KERN-14). This is the kernel-to-collector bridge -- a bounded mpsc channel collects events, a background task compresses with zstd and streams to the evidence collector via gRPC every 500ms. Evidence loss under backpressure is acceptable (fail-open for evidence); adding latency to AI responses is not.

Output: New `evidence` module in the kernel crate with EvidenceBuffer, RawEvidenceEvent, background flusher, and gRPC client.
</objective>

**5. Create `crates/kernel/src/evidence/mod.rs`:**
Implement `EvidenceBuffer` following 04-RESEARCH.md Pattern 1 (lines 188-244):
```rust
pub mod bundle;
pub mod client;

use tokio::sync::mpsc;
use std::time::Duration;

const EVIDENCE_BUFFER_SIZE: usize = 8192;
const FLUSH_INTERVAL: Duration = Duration::from_millis(500);
```

- `EvidenceBuffer` struct with `tx: mpsc::Sender<RawEvidenceEvent>`
- `EvidenceBuffer::new(collector_addr: String, kernel_id: String) -> (Self, tokio::task::JoinHandle<()>)`:
  - Creates bounded `mpsc::channel(EVIDENCE_BUFFER_SIZE)` -- KERN-13 compliance (bounded channels)
  - Spawns background flusher task
  - Returns the buffer handle and the task join handle
- `EvidenceBuffer::try_send(&self, event: RawEvidenceEvent)`:
  - Uses `tx.try_send(event)` -- non-blocking
  - If buffer full, log `tracing::warn!("evidence buffer full, dropping event")` and discard
  - Per anti-pattern: NEVER await on send. NEVER block the proxy hot path.
- `EvidenceBuffer::stub() -> Self`:
  - Creates a buffer that drops all events (for tests that don't need evidence)
  - Uses a disconnected sender

Background flusher function `evidence_flusher`:
- Receives from mpsc channel
- Uses `tokio::select!` between interval tick (500ms) and channel receive
- On interval tick: if batch is non-empty:
  1. Convert events to proto EvidenceBundle messages using `to_proto_bundle`
  2. Serialize bundle vec with prost
  3. Compress with `zstd::encode_all(&serialized[..], 3)` (compression level 3 -- fast, per user decision)
  4. Send via `EvidenceGrpcClient::submit_batch`
  5. Clear the batch
  6. Increment batch_sequence counter
- On channel receive: push event to local batch Vec
- On channel closed: flush remaining batch and exit
- Pre-allocate batch Vec with capacity 256

Unit tests:
- `try_send` does not block even when buffer is full
- `EvidenceBuffer::stub()` silently drops events
- `RawEvidenceEvent` -> proto conversion preserves all fields
