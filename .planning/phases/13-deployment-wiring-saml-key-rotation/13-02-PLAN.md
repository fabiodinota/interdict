   ```yaml
     # -- SP base URL (control plane external URL for ACS callback)
     spBaseUrl: ""
     # -- Dashboard URL for post-login redirect
     dashboardUrl: ""
   ```

   ```yaml
   ---

   kind: PersistentVolumeClaim
   metadata:
     name: {{ include "interdict.fullname" . }}-signing-keys
     labels:
       {{- include "interdict.labels" . | nindent 4 }}

       - ReadWriteOnce
     resources:
   ```

   This follows the exact same pattern as the existing certs PVC. ReadWriteOnce is sufficient for single-replica pilot deployments where control-plane and evidence-collector are on the same node.

2. **control-plane deployment.yaml** -- Add signing-keys and config volume mounts:

   a. In the container's `volumeMounts:` section, after the certs mount, add:
   ```yaml
           - name: signing-keys

           {{- end }}
   ```

   b. In the `volumes:` section, after the certs volume, add:
   ```yaml
       - name: signing-keys
         persistentVolumeClaim:
           claimName: {{ include "interdict.fullname" . }}-signing-keys
       {{- if .Values.controlPlane.saml.enabled }}
       - name: saml-config
         {{- if .Values.controlPlane.saml.existingIdpMetadataSecret }}
         secret:
           secretName: {{ .Values.controlPlane.saml.existingIdpMetadataSecret }}
         {{- else }}
         emptyDir: {}
         {{- end }}
       {{- end }}
   ```

   The saml-config volume mounts IdP metadata from an existing Secret when provided. If no secret is specified but SAML is enabled, an emptyDir placeholder is used (operator must provide metadata via another mechanism or the SAML init will skip due to missing file).

   Note: These env vars are for runtime reference/documentation. Since Next.js inlines NEXT_PUBLIC_ at build time, the dashboard image must be built with these values baked in. The Helm values serve as documentation of what build-time values the image expects.

5. **configmap-cert-script.yaml** -- Add SAML SP certificate generation to the cert-init script. After the kernel-client generate_service_cert call (line ~70) and before the chmod block, add:

   ```
   # SAML SP self-signed certificate (3-year validity)
   if [ ! -f "${CERT_DIR}/saml-sp.key" ]; then
       echo "[cert-init] Generating SAML SP certificate..."
       openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 \
           -days 1095 -nodes \
           -keyout "${CERT_DIR}/saml-sp.key" \
           -out "${CERT_DIR}/saml-sp.crt" \
           -subj "/CN=interdict-saml-sp/O=Interdict"
       echo "[cert-init] SAML SP certificate generated."
   else
       echo "[cert-init] SAML SP certificate already exists, skipping."
   fi
   ```

   This is idempotent (checks for existing saml-sp.key) and follows the same ECDSA P-256 pattern as the other certs. Self-signed because SAML SP certs are registered directly with the IdP.
