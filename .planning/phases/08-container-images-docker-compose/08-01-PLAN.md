**docker/kernel/entrypoint.sh** — Shell script:
```sh
#!/bin/sh
set -e

# Generate interdict.toml from template if not mounted by user
if [ ! -f /app/interdict.toml ] || [ "${KERNEL_FORCE_TEMPLATE:-false}" = "true" ]; then
    echo "[entrypoint] Generating interdict.toml from environment variables..."
    envsubst < /app/interdict.toml.template > /app/interdict.toml
fi

# Auto-generate CA cert/key if not present (pilot convenience)
if [ ! -f /data/certs/ca.crt ]; then
    echo "[entrypoint] Generating self-signed CA certificate..."
    openssl req -x509 -newkey ed25519 \
        -keyout /data/certs/ca.key \
        -out /data/certs/ca.crt \
        -days 3650 -nodes \
        -subj "/CN=Interdict CA/O=Interdict"
    chmod 600 /data/certs/ca.key
    echo "[entrypoint] CA certificate generated at /data/certs/ca.crt"
fi

echo "[entrypoint] Starting Interdict kernel..."
exec /usr/local/bin/interdict-kernel /app/interdict.toml
```

IMPORTANT: envsubst replaces ALL `${VAR}` patterns. The `:-default` syntax is handled by the SHELL, not envsubst. For envsubst to work with defaults, the entrypoint must use `envsubst` on a file where the env vars are either set or have shell defaults. Since envsubst does NOT evaluate `:-` syntax, the template must use bare `${VAR}` placeholders and the entrypoint (or env.example) must define all variables with their defaults. Update the template to use bare `${KERNEL_LISTEN_ADDR}` and ensure env.example provides defaults. The entrypoint should set defaults for unset variables BEFORE calling envsubst:

```sh
# Set defaults for unset variables
: "${KERNEL_LISTEN_ADDR:=0.0.0.0:8443}"
: "${KERNEL_CONNECT_TIMEOUT_MS:=10000}"
# ... etc for each variable
envsubst < /app/interdict.toml.template > /app/interdict.toml
```

This is the correct pattern. Update the entrypoint to include all kernel variable defaults before the envsubst call.
