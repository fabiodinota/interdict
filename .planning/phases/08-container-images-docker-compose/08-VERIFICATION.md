### Human Verification Required

#### 1. Full Stack Smoke Test

**Test:** On a machine with Docker Engine installed, run:
```sh
cp env.example .env
docker compose up
```
**Expected:** All 8 services start and the health checks pass in the following order: postgres, clickhouse, minio (healthy) → minio-init (completes, creates interdict-evidence bucket) → control-plane (healthy after migrations/seed) + evidence-collector (starts) → kernel (starts after control-plane healthy) → dashboard (starts). `docker compose ps` should show all services as `Up` or `Exited 0` (for minio-init).

**Why human:** Cannot build container images or run Docker in a static code verification pass. First-boot automation (CA cert generation, Drizzle migration, seed) can only be confirmed live.

#### 2. MinIO Healthcheck Runtime Behavior

**Test:** Observe whether the `minio` service transitions to the `healthy` state. Run:
```sh
docker compose up minio
docker inspect --format='{{.State.Health.Status}}' $(docker compose ps -q minio)
```
**Expected:** Status transitions from `starting` to `healthy` within 60 seconds (10s start_period + 5 retries × 5s interval).

**Why human:** The healthcheck command is `CMD mc ready local`. This requires (a) the `mc` CLI binary to be present in the `minio/minio` image (present in MinIO server images since 2023, bundled at `/usr/bin/mc`) and (b) a pre-configured `local` alias pointing to `http://localhost:9000`. Recent MinIO releases pre-configure this alias, but the behavior varies by image version. If the healthcheck fails, `minio-init` never runs, the evidence bucket is never created, and `evidence-collector` never starts — blocking the entire startup chain. Alternative healthcheck if this fails: `wget -q --spider http://localhost:9000/minio/health/live`.

#### 3. Control Plane Health After First Boot

**Test:** After `docker compose up`, verify the control plane health endpoint:
```sh
curl -s http://localhost:3000/health
```
**Expected:** Returns `{"status":"ok","timestamp":"..."}` with HTTP 200.

**Why human:** The health endpoint only becomes live after Drizzle migrations run successfully against Postgres and the seed script completes. If migrations fail (schema mismatch, connection timeout), the health endpoint may never respond and the kernel will never start.

#### 4. Kernel CA Cert Auto-Generation on First Boot

**Test:** After the stack is running, inspect the kernel container:
```sh
docker compose exec kernel ls -la /data/certs/
docker compose exec kernel cat /app/interdict.toml
```
**Expected:** `/data/certs/ca.crt` and `/data/certs/ca.key` exist and are owned by `interdict` user. `/app/interdict.toml` contains substituted values (e.g., `listen_addr = "0.0.0.0:8443"` not `"${KERNEL_LISTEN_ADDR}"`).

**Why human:** First-boot CA cert generation and envsubst templating require a running container to confirm.
