| D032 | release-please (simple mode) over manual changelog + standard-version | Fully automated: creates release PRs, bumps versions, updates CHANGELOG, creates tags. Google-maintained. `release-type: simple` suits non-publishable monorepo. | 2026-03-15 |
| D033 | Benchmark CI tracking with 200% alert threshold, main-only, no PR gating | GitHub Actions VM noise makes tight thresholds produce false positives. Track trends with generous threshold; tighten later with dedicated runners. | 2026-03-15 |
| D034 | TruffleHog `--results=verified,unknown --fail` for secret scanning | Filters out unverified false positives while catching confirmed secrets and unknowns that need investigation. `--fail` blocks pipeline on findings. Full history scan via `fetch-depth: 0`. | 2026-03-15 |
| D035 | CSP nonce middleware replaces static CSP headers; refactor inline styles to eliminate `unsafe-inline` | Per-request nonce via `crypto.randomUUID()` in Next.js middleware. `strict-dynamic` for script chaining. | D036 | Helm NetworkPolicy enabled by default with CNI documentation | All 4 service network policies already have correct ingress/egress rules — flip default to `true`. Document CNI requirement (Calico/Cilium) and how to disable for unsupported environments. Breaking change for existing deployments documented in CHANGELOG. | 2026-03-15 |
| D037 | kube-score pinned version + known-issue ignore flags in CI | Pin kube-score version to avoid surprise CI breaks from new checks. `--ignore-test container-image-pull-policy` (Helm uses appVersion tags, not `:latest`) and `--ignore-test pod-topology-spread-constraints` (single-replica dev defaults). | 2026-03-15 |
| D038 | Docker Compose monitoring profile (Prometheus+Grafana) is opt-in via `--profile monitoring` | Monitoring stack adds ~500MB of image pulls — must never start by default. Operators use `docker compose --profile monitoring up` explicitly. Production deployments have their own monitoring; this is for dev/staging only. | 2026-03-15 |
| D039 | .dockerignore allowlist pattern: exclude broadly, re-include build-essential paths | Safer than selective exclusion — new non-build files are excluded by default. Allowlist (`!proto/`, `!crates/`, `!control-plane/`, `!dashboard/`, `!docker/`, `!Cargo.toml`, `!Cargo.lock`) explicitly names what each Dockerfile needs. | 2026-03-15 |
| D040 | TARGETARCH for architecture-dependent binary downloads in Dockerfiles | Docker Buildx provides `TARGETARCH` automatically (amd64/arm64). OPA release naming matches exactly — no translation needed. Pattern reusable for any future binary downloads. | 2026-03-15 |
| D041 | kube-score ignore list: 13 checks covering third-party subchart + Helm dev-default issues | Bitnami subcharts (postgresql, clickhouse, minio, zookeeper) trigger user-group-id, readonlyrootfilesystem, ephemeral-storage, PDB, pod-probes, anti-affinity checks not fixable in our templates. Helm dev defaults trigger deployment-replicas, deployment-strategy. All documented as known-issues. | 2026-03-15 |
| D042 | Manual API docs over `@elysiajs/openapi` runtime integration | Manual REST/gRPC reference docs provide better editorial control and avoid Elysia version compatibility risk. 53 endpoints across 13 modules are typed with TypeBox but documented as human-readable markdown rather than auto-generated OpenAPI. Runtime `/api/docs` endpoint can be added later if needed. | 2026-03-15 |
| D043 | vitest-axe `color-contrast` rule disabled in happy-dom environment | happy-dom doesn't implement CSSOM, so color-contrast checks produce false negatives. Disable in vitest-axe config; rely on Playwright `@axe-core/playwright` for browser-level WCAG validation including color-contrast. | 2026-03-15 |
| D044 | Docker base images pinned by manifest-list digest, not per-architecture digest | Manifest-list digests let Docker automatically select the correct platform at pull time while remaining immutable. Tags preserved alongside digest for human readability. Renovate docker pinDigests covers automated updates. | 2026-03-15 |
| D045 | GitHub Actions pinned to SHA digests with `# version` comments | Eliminates mutable tag/branch supply chain risk (cosign-installer@main, trufflehog@main were highest risk). Format: `uses: owner/action@<sha> # <version>`. Renovate pinDigests:true tracks updates. All 45 refs across 3 workflows pinned. | 2026-03-15 |
| D046 | OPA binary verified by per-architecture ARG checksums with TARGETARCH conditional | Replaces unverified ADD with curl + sha256sum -c. Checksums pinned as build ARGs for amd64/arm64. Build fails immediately on mismatch — fail-closed. No extra network request for checksum file at build time. | 2026-03-15 |
| D047 | Per-route beforeHandle for rate limiting instead of Elysia onBeforeHandle plugin | Elysia 1.4 onBeforeHandle in .use() plugins doesn't short-circuit requests. Per-route beforeHandle via createRateLimitHook() factory works correctly. Pattern: .post("/path", handler, { beforeHandle: createRateLimitHook(limiter) }). | 2026-03-15 |
| D048 | Raw SQL subquery for batched cleanup deletes (DELETE WHERE id IN SELECT LIMIT N) | Drizzle ORM 0.45 PgDelete lacks .limit() method. PostgreSQL natively supports DELETE WHERE pk IN (SELECT pk ... LIMIT N) for bounded batch deletes. Avoids unbounded transaction duration on large tables. | 2026-03-15 |
| D049 | TypeBox maxLength tiers: id/key=255, name=500, url=2000, notes=5000, description=10000, rego_source=500000 | Semantic-based limits prevent multi-megabyte payloads while accommodating realistic field sizes. Rego policies can legitimately be large; URLs rarely exceed 2K. | 2026-03-15 |
| D050 | Dual-layer body size limit: onRequest Content-Length check + Bun maxRequestBodySize | onRequest produces structured JSON 413 ({ code: "BODY_TOO_LARGE", maxBytes: N }) for API clients. Bun maxRequestBodySize serves as backstop for missing Content-Length. MAX_BODY_SIZE env var controls both (default 1MB). | 2026-03-15 |
| D051 | CSV escapeCSV() fail-closed for negative numbers (formula prefix "-") | String(-1) starts with "-", triggering sanitization. Intentional fail-closed — security over convenience for CSV output consumed by Excel/Sheets. | 2026-03-15 |
| D052 | Grafana ADMIN_PASSWORD uses :? (required) syntax, ADMIN_USER uses :- (optional default) | Password must be fail-closed — compose refuses to start without it. Username defaults to admin for convenience. Matches the existing credential parameterization pattern used by Postgres, ClickHouse, and MinIO. | 2026-03-15 |
| D053 | apk --root /tmp/apkroot for readOnlyRootFilesystem init containers | cert-init needs openssl but readOnlyRootFilesystem prevents apk install to /usr. Installing to tmpfs-backed /tmp/apkroot preserves the existing alpine base image while enabling full rootfs read-only. Pattern reusable for any init container needing runtime package installation. | 2026-03-15 |
| D054 | ServiceAccount with automountServiceAccountToken: false by default | Minimal attack surface: pods get RBAC-bound SA identity without auto-mounted tokens. Explicit opt-in via annotations (e.g., AWS IRSA) when cloud provider binding is needed. Role limited to secrets+configmaps get/list. | 2026-03-15 |
| D055 | Integration test profile: docker-compose.test.yml override with ephemeral volumes and remapped ports | Test profile uses deterministic dev credentials (no .env needed), test-prefixed volumes destroyed on `docker compose down -v`, ports remapped to 1xxxx range to avoid dev-instance conflicts. Dashboard excluded via profiles. Orchestration script auto-discovers test scripts in tests/integration/. | 2026-03-15 |
| D056 | Integration tests bootstrap auth via direct psql insert of known API key hash | Seed script generates random API keys that can't be retrieved by test scripts. Direct insert of a deterministic key hash (SHA-256 of a known plaintext) makes tests idempotent and self-contained. Pattern: compute hash locally, INSERT INTO api_keys with ON CONFLICT DO NOTHING. | 2026-03-15 |
| D057 | COOKIE_SECURE env var override for cookie secure flag | Staging environments need explicit control over cookie `secure` flag independent of NODE_ENV. Pattern: check `COOKIE_SECURE` env var first (`"true"` → true), fall back to `NODE_ENV === "production"` when unset. Allows staging with HTTPS to set `true` and local dev behind reverse proxy to set `false`. | 2026-03-15 |
| D058 | Vendored buf/validate/validate.proto under proto/third_party/ for protoc compatibility | tonic_prost_build calls protoc directly and cannot resolve buf BSR dependencies. Vendoring the proto file ensures Rust builds and buf lint both work. buf.yaml excludes proto/third_party to avoid duplicate symbol errors with the BSR dep. | 2026-03-15 |
| D059 | CA validity reduced from 10 years to 1 year with 30-day expiry warning | 10-year CA validity (L-09) was excessive for mTLS certs. 1-year aligns with industry best practice. Cert-init emits structured `[certs] WARNING` to stderr when any cert expires within 30 days. 30-day threshold chosen to balance early warning vs alert noise. | 2026-03-15 |
| D060 | Testable retry loop via `#[cfg(test)]` closure-based `retry_with_backoff` | Production commit retry uses `commit_with_retry()` operating on the real `Inserter`. Tests use `retry_with_backoff()` accepting `FnMut` closures — avoids needing ClickHouse for unit tests while validating retry count, backoff, dead-letter, and health counter behavior. | 2026-03-16 |
| D061 | `pending_rows` Vec buffers rows since last successful commit for dead-lettering | The clickhouse crate `Inserter` may lose its internal buffer on `commit()` failure. We clone each `EvidenceRow` into a `Vec` before writing to the inserter; on retry exhaustion, all buffered rows are dead-lettered. Cleared on successful commit. | 2026-03-16 |
