# T03: Department self-referencing FK and dead code removal

**Added self-referencing FK on departments.parentDepartmentId (ON DELETE SET NULL) and fully removed dead rolePermissions table from schema, exports, and seed script.**

## What Happened

1. Added `.references(() => departments.id, { onDelete: "set null" })` to `parentDepartmentId` in `organization.ts`. Drizzle's arrow function pattern defers resolution for self-references.

2. Removed `rolePermissions` table definition from `auth.ts`, its re-export from `schema/index.ts`, and the seed block + import from `run-seed.ts`. Also cleaned up the now-unused `uniqueIndex` import from auth.ts and updated stale doc comments in auth.ts, run-seed.ts, and permissions.ts that referenced the removed table.

3. `drizzle-kit generate` couldn't handle the delta because migration 0003 was hand-written without a journal entry or snapshot — drizzle-kit mistook the rolePermissions removal for a rename. Wrote migration 0004 by hand following the same pattern as 0003, containing the FK constraint and table drop with index cleanup.
